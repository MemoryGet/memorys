# 原件粗粒度文本引用核验

`VerifyOriginalTextEvidence` 已实现一个原件、一个文档版本的批量文本引用核验，依赖标准正文读取、独立原件授权、BlobStore及可替换的OriginalTextProjector。

流程：

1. 在调用提供者前复制并验证Evidence，固定Document、Revision、Block、Blob和摘录；只接受文件级original/coarse定位。
2. 新读取并核验批准冻结正文双摘要。指定块必须是文本块，来源锚点须与Evidence完整匹配，摘录须存在于该批准块正文中。
3. 从批准Blob清单取得文件元数据，经独立当前授权读取实际原件并核验长度、SHA-256及流终态。只捕获这一次已核验流中的字节，避免核验后另外读取一份未验证数据交给文本提供者。
4. 将已核验字节的独立副本交给文本投影器，投影调用同时受最新原件读取授权期限限制。摘录还必须存在于实际原件投影中。
5. 投影完成后再次核验原件字节、原件授权和批准正文；期间观察到撤权、撤回、正文失效或原件损坏时拒绝。

默认UTF8OriginalText只支持UTF-8的text/plain及text/markdown，保留原始文本，不进行有损解码或替换。PDF、Office及OCR可通过同一文本投影接口接入成熟组件，但仍需独立验证配置、版本和效果；当前没有默认实现或替换验收证据。

单调用最多1000条Evidence，摘录累计最多4 MiB，一个原件最多8 MiB，投影文本最多4 MiB。原件会完整读两次，尚未进行生产规模延迟和并发验收。远程提供者必须遵守取消与可信数据投影契约；声明版本或返回一段匹配文本本身不能证明其解析行为真实。

实际本地文件测试覆盖完整正向流程、提供者修改调用方Evidence后的隔离、错误文档/版本/块/Blob/摘录、额外几何定位、多原件、损坏字节不进入投影器、投影期间批准失效和不支持的编码/格式。

人工新增且仅存在于批准正文中的文字不能被当作原件引文，即使该编辑已经审核通过。需要保留正确的版本引用及派生来源，不能在校验器中将original改写成revision来跳过验证。

当前不验证页码、单元格、表格结构、图片框、音频时间或OCR语义；这些定位明确拒绝，不降低成粗粒度通过。本轮仍是本地组合验证，尚未接入PostgreSQL、CurrentBackend/CurrentControl、模型或REST/MCP输出，不构成完整输出授权或跨系统撤销屏障。

OriginalTextProjector目前是进程内策略端口。远程协议、注册工厂、模块调用授权和完整替换试验均未实现，不能把局部接口注入测试算作生产独立模块替换验收。
