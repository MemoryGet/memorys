# 解析候选持久化事务

平台领域层定义CandidateRepository.CommitCandidate，PostgreSQL候选实现独立于解析供应商。当前适配的是隔离验证Schema，不是完整MetadataRepository/UnitOfWork或生产迁移。

命令包含平台DocumentID/CandidateID、原件与预期草稿版本、流水线摘要、解析器版本、候选内容及当前AccessScope。同步写入要求可信Verify回调授权当前主体的候选写入，开始和提交边界均检查；它不能替代后台任务的Lease、Attempt和Fencing验证。当前接口没有后台任务完成能力，不能作为worker回执使用。

事务使用Serializable隔离，锁住未删除的文档与目标草稿。目标草稿必须在相同空间/知识库/文档内。合并规则满足时CAS更新草稿及其JSON载荷；版本变化、提交或附件变化时不覆盖草稿，仍保存独立候选及原因。候选、提交回执、审计和outbox在同一事务写入，审计/outbox失败会回滚草稿更新。数据库的延迟约束要求候选写入同时存在匹配主体的审计和匹配回执的outbox。

幂等采用空间/知识库内CandidateID，绑定主体、文档和完整候选的格式化请求摘要。相同ID/相同内容返回原始回执，不重新合并；不同内容或主体不得接管已有ID。候选与审计记录禁止修改。调用开始时再次确认文档仍可访问，重放不会绕过当前授权。提交结果未知时返回无成功回执，调用方必须用相同ID重放/核对，不能新分配ID盲重试。

解析在事务外执行；不可将长时间模型/解析调用放进草稿行锁。当前仓储接受平台已验证的候选，但输入内容的完整结构、真实制品身份、任务产出绑定及当前授权仍须由上游履行。生产数据库角色、RLS、完整审核状态机、候选读取/编辑API、任务回执、迁移日志及导出回退均未完成。

隔离PG探针覆盖正常CAS、冷连接回执重放、同ID不同内容拒绝、迟到和已提交草稿的候选保留、写入后审计失败全回滚、提交前权限撤销回滚及候选不可变。授权/解析结果是fixture；真实解析器与该仓储尚未接到同一业务端点。具体验证结果见数据库证据报告，不能以源码声明代替运行结果。

当前真实证据（2026-10-15）：当前SQL及仓储/应用探针已在PG15.19/16.15/18.6全部执行同一套54项检查，源码输入和Go二进制一致。包含候选CAS、冷连接重放、迟到/已提交候选保留、审计/outbox故障回滚、读取及真实文件应用链路。服务、私有目录和端口清理均已核对，见[多版本矩阵](POSTGRES_VERSION_MATRIX.md)。完整UoW、真实IAM/RLS、任务租约、审核发布、迁移回退和生产部署仍未完成。

资源授权增量：适配器现在同时强制VerifyScope和AuthorizeCandidate。后者收到独立副本的完整平台命令，须核对当前主体对具体Document/Draft/原件候选的写入授权；不能只验证scope或把解析读取授权当作写授权。事务开始、操作入口和提交前都会调用组合验证器，回执重放也执行当前资源授权。回调不应要求草稿仍处于原预期版本，否则会破坏正常幂等重放；版本与提交状态由事务内CAS决定。

输入命令首先反序列化到新的零值对象，避免encoding/json复用原切片底层数组。授权方每次收到新的独立副本；请求摘要、候选载荷和草稿合并始终使用同一个冻结命令。四项Go驱动替身测试覆盖缺失/拒绝授权不开始SQL、提交前资源撤权回滚、回调参数修改隔离，以及回调期间调用方底层数组变化不会改写提交内容。这些测试仅验证控制流与数据所有权，不证明真实数据库语法、锁、约束或持久化，PG验收状态不变。

当前已实现SQL与仓储事务另已在PG15.19/16.15/18.6真实执行同一套54项检查，且源码与Go探针二进制一致。该证据补齐当前子集的PG15/18兼容缺口；完整UoW、真实权限、审核发布、迁移回退及生产部署仍保持开放。见[多版本矩阵](POSTGRES_VERSION_MATRIX.md)。
