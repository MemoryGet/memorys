# 重新认证与当前授权控制编排

2026-10-16：新增 `queryread.AuthenticatedControl`，实现CurrentControl，绑定一份已准备的CheckOperation。每次Refresh均重新调用标准Authenticator和Authorizer，再从CurrentFactsSource读取当前流水线配置及审核规则；不直接复用传入Principal或旧Scope作为授权结果。

## 输入与边界

构造时必须提供三个非空提供者和临时凭据。保存操作、请求身份、原始范围、必要知识库及文档资源的独立副本；Refresh不能换用另一请求、延长期限或更换原主体。重新认证后的主体/发行方/客户/委托必须保持绑定，授权范围不得扩大且须覆盖所有实际来源。配置摘要变化、缺少当前审核规则或提供者失败时拒绝。

Authorizer接收刚重新认证的主体，以及保存操作的动作、空间、知识库和文档资源。CurrentFactsSource必须核实当前范围、读取实际可信配置/规则，不能把请求摘要原样回显作为真实配置，也不能用未验证缓存冒充当前事实。

凭据只保留在请求实例私有内存中，限制16 KiB。传给Authenticator的是独立临时副本，认证结束即清除；Close清除实例持有副本并拒绝后续刷新。普通字符串/调试字符串及JSON表示均不输出凭据。提供者仍受可信模块准入约束，宿主须对每次请求调用Close，不能把该对象作为长期凭据库。

刷新按实例串行执行；Close等待当前刷新离开，提供者必须遵守请求及Scope期限。该服务不实现令牌签发、JWT/OIDC验证、真实用户目录、权限持久化、RLS或Grant账本；这些仍是必须接入并验收的独立适配器。

## 验证范围

专项检查覆盖两次完整认证/授权/规则读取、凭据副本与擦除、提供者修改参数后的隔离、身份变化、扩权、权限失败、配置变化、规则缺失、重绑定请求、取消/无期限、关闭后拒绝及日志表示脱敏。后端处理期间凭据撤销会在最终重新认证时停止，不能进入后续授权。

原有PG证据探针的正向CheckCurrent改用该编排器：Authenticator/Authorizer仍为明确标记的测试提供者，当前审核规则读取真实数据库，索引/冻结正文/原件均实际核验。不将它称为生产IAM，也不据此关闭整体CHECK或产品输出验收。

## 当前证据

[专项本地记录](evidence/authenticated-control-local-review.json)及[实库证据后端复核](evidence/evidence-backend-runtime-review.json)已归档。同一479项输入与同一Go探针在PG15.19/16.15/18.6各通过184项检查，三组正向操作均记录认证/授权各两次；真实索引、正文和原件核验保持通过。Go全量测试/vet、228项Python、三份OpenAPI、成熟四格式及双PDF引擎回归通过，PG目录/端口清理已独立核对。

服务本身可替换认证/授权提供者，尚无生产CurrentFactsSource、身份适配器或权限持久化的验收证据；不能据此宣称生产授权、独立模块部署或最终API/MCP输出完成。
