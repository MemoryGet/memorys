# 检索性能运行 Harness

`pkg/retrieval.RunBenchmark`提供与具体检索引擎无关的有界性能采样器。宿主传入已装配的检索回调和每次调用的候选字节/成本代理计量；Harness只负责固定请求数、并发上限、单请求deadline、失败分类和延迟分位数。

每个样本都在固定`RequestTimeout`下执行，worker数量不超过`Concurrency`，请求队列不会无限增长。回调必须响应context；父context取消后，Harness等待已启动worker退出并返回取消错误。回调失败进入`Failed`，deadline进入`TimedOut`，成功样本才累计候选字节与CostUnits。CostUnits是平台计量单位，不自动换算商业费用。

报告输出请求数、完成/失败/超时、峰值并发、候选字节、CostUnits和P50/P95/P99延迟。分位数按排序后的最终样本位置计算，失败和超时仍占用延迟样本但不计入成功输出成本。Warmup样本不进入报告。

这个Harness验证执行边界、取消和计量采集，不证明引擎质量、Recall@10、代表性中文数据、真实供应商费用或生产硬件吞吐。正式验收仍需固定封存集、权限/发布快照、模型/索引版本、缓存条件、并发矩阵和独立实验轨迹；Recall算术继续由`retrieval_evaluation.py`负责。

当前本地测试覆盖并发上限、分位数、失败/超时分类、计量累加和无deadline/无效预算拒绝。尚无真实中文封存集或生产规模性能结果。

## 正式检索负载与稳定性入口

`run_formal_performance.py`固定正常矩阵为32/100/500份资料×关键词/语义×并发1/2/4×三轮，每格1000次，共54000次；先跑500份语义并发4。通过后执行过载观察、1/2/3请求每秒的混合固定到达率，以及各一次2小时和8小时的1请求每秒混合检索。1请求每秒为名义工况，2/3用于容量边界观察，允许429但不接受连接/正确性错误。任一必需门槛失败即停止后续阶段，不能用其他格平均值掩盖失败。6次真实问答仅为有总量上限的冒烟检查，不构成问答延迟统计验收。

`--smoke`只验证运行器，不能产生正式通过结论。运行器固定应用二进制/源文件/前端/模型和公开合成语料摘要，在自有临时实例中创建32/100份数据库快照，复用同一安装的受保护状态目录。每格重启并预热宿主，稳定性阶段保持同一进程；网页会话按原两小时时限从正常入口续开，调度/排队/续开等待计入固定到达率延迟，失败不重试。来源检查包含精确文档、版本、块、全文哈希、排名及引用绑定；逐请求记录足以与公开语料清单独立复核。

`STATUS.md`和`report.json`持续更新，结束时生成`RESULTS.md`和摘要清单。需要取消时，在该输出目录创建`CANCEL`文件，控制器会停止并清理自有进程/数据库。运行期间请求系统保持唤醒，允许屏幕关闭，退出时恢复线程电源状态。源码/前端改变、证据保存失败、明显墙钟跳变或不连续采样均不能判为有效通过。内存/句柄采用第10～20分钟和末10分钟中位数比较，并记录数据库连接与存储增长；具体预算在报告中先于测量固定。

本入口的`local_retrieval_performance_acceptance`只描述这组固定条件下的检索范围；`local_performance_acceptance`和`production_acceptance`保持false，其他多格式、浏览器、中文质量、费用及生产门槛不会由长测自动关闭。

`--reference-baseline`指定已完成且源码/前端未变的小样本筛查报告；当前应用源码、构建二进制、模型及语料必须与它相符。修改应用后先重新建立小样本基线，再传入新报告，不覆盖旧轨迹。闭环负载每个worker只领取下一个请求，取消后未发出的请求不生成样本，主动中止只能形成未完成结论。
