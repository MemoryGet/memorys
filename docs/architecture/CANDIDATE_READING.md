# 候选读取与提交核对

平台领域层定义独立CandidateReader.ReadCandidate，输入平台DocumentID、DraftID、CandidateID及当前读取授权。输出候选、原提交主体和原始回执，不改变草稿、审批或发布状态。

PostgreSQL候选实现要求精确动作document.candidate.read和独立AuthorizeRead回调，不能从document.parse或候选写入授权推导读取权。范围校验、资源授权在事务开始、操作入口及返回前执行；每次回调收到独立请求副本，不能通过scope切片改写SQL目标。查询限定空间/知识库/文档/草稿/候选完整路径，并排除已删除文档；文档共享锁保持本次读取事务内的删除顺序。

读取后校验候选结构、原件归属和版本绑定，使用原提交主体重算akos.draft-candidate/1请求摘要，核对回执ID、版本及保留原因。当前审核者可以与提交者不同，但必须有可信资源读取授权。所有失败统一返回不可用/无权错误和空记录，避免把半校验内容泄露给调用者。这是数据一致性核对，不是数据库遭任意篡改后的密码学真实性证明。

未知提交可在获取新的有效读取授权后按原ID核对：找到且验证通过的记录提供原始提交回执；缺失、无权或暂不可见统一不构成“之前没有提交”的证据。原写事务可能尚在运行，不能因读不到记录就分配新ID或重做业务。跨重启恢复仍需持久保存原始准备内容、主体/委托绑定、任务租约和迁移水位，该协议尚未实现。

四组驱动替身测试覆盖正常跨主体读取、返回值独立副本、错误候选/主体/摘要/回执及缺失结果、独立读取权、提交前撤权丢弃结果、回调修改与调用方数组修改隔离。真实数据库中的冷连接读取、原主体摘要和回执核对及资源拒绝，已随同一套54项探针在PG15.19/16.15/18.6全部通过，服务和私有目录均已清理。见[多版本矩阵](POSTGRES_VERSION_MATRIX.md)。授权回调仍是fixture，生产角色/RLS、当前IAM和业务端点仍未验收。
