# 配置快照与实际模块装配

更新：2026-10-16。实现 `pkg/profileassembly`、内核具名绑定检查与解析；三版PG原生运行和独立样本关系验证已通过。

## 装配流程

读取并校验完整平台配置快照 → 选择查询或索引阶段 → 收集该阶段全部默认绑定和路由绑定 → 内核校验具名实例/能力/契约版本/所需特性 → 按依赖创建模块并执行健康检查 → 按路由解析标准接口。

`kernel.BuildBound` 在创建任何模块前检查全部具名绑定，不只检查某个能力的部署默认值。`Runtime.GetBound` 按具名实例解析，并再次检查声明。`profileassembly.Build` 保持已校验快照的独立副本，返回的 Profile 和内核 Identity 也是副本。

同一个能力可以存在多个实例，路由独立指向各自实现。QueryProfile.Bindings 是默认绑定；Routes 中的 Binding 可以指向同能力的另一个实例。`ResolveRoute[T]` 使用路由绑定，`Resolve[T]` 使用阶段默认绑定。配置摘要覆盖各路由引用，不能通过修改默认值悄悄改变另一条路由。

## 阶段与生命周期

查询与索引可以在不同进程装配。查询阶段只验证和装配提供的查询计划，不能据此宣称索引写入能力已具备。索引阶段要求对应 IndexWriter 等完整接口；原生 PreparationIndex 只实现受控发布准备接口，不能冒充完整 IndexWriter。

关闭运行时后新解析失败。已交出的接口引用是否拒绝调用，需要实现自身管理生命周期；内核不能自动撤销任意 Go 接口引用。本轮 PostgreSQL 检索适配实例用读写锁管理关闭状态，关闭等待已进入的检索完成，旧引用随后拒绝搜索。此保证限于该适配实例，不自动扩展到所有第三方模块。

平台配置摘要与内核装配 ConfigVersion 分开记录：前者承诺逻辑配置内容，后者记录解析后的提供方、实现版本、设置与模块声明。保持逻辑绑定不变而更换提供方时，前者可以保持稳定，后者应改变。实际制品内容真实性仍需制品锁验证。

## 验证与边界

单元测试覆盖同能力双实例路由、提供方替换、返回快照副本、关闭后的解析及托管引用拒绝；缺失实例、错误契约主版本和缺少特性均在创建前失败；查询部署不能通过索引阶段装配。

原生探针使用实际 PostgreSQL KeywordRetriever，经配置快照与注册工厂装配后按路由调用，返回真实数据库候选。样本记录配置、装配身份、路由、候选及关闭拒绝；独立 Python 核对这些关系。

装配层只负责配置与模块声明、接口及生命周期的连接，不替代查询规划/预算执行、身份授权、制品真实性验证或部署初始化。当前数据库依赖与工厂由受控探针注入，尚非正式生产 Bootstrap。

尚缺生产部署归一化、制品锁验证、凭据注入、全部阶段的工厂、完整索引模式语义，以及配置迁移/回退和 REST/MCP/UI 产品服务验收。
