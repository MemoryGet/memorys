# 架构验证与实施门槛

## 1. 分阶段交付

| 阶段 | 交付 | 进入下一阶段的证据 |
|---|---|---|
| A 架构 | 边界、数据模型、端口、状态机、决策和验证方案 | 文档可追溯、关键一致性场景已明确；待验证项显式列出 |
| B 契约基础 | Go DTO、JSON Schema、OpenAPI、注册装配、启动验证 | 契约一致性、无厂商类型泄漏、配置错误拒绝启动 |
| C 治理闭环 | 接入原件→草稿编辑→审核→索引准备→发布→检索/读取→撤回 | 权限、版本、故障、幂等、备份恢复场景通过 |
| D 成熟组件验证 | 多格式解析、独立/复合检索、云模型适配 | 两种实现替换对照；记录版本、许可、导出与效果 |
| E 产品集成 | Vue 界面、REST/MCP、回答、反馈、有限反思 | 伙伴同一身份同一结果；引用与预算测试通过 |
| F 质量与迁移 | 中文评测、固定负载、替换、回退和运维手册 | 质量门槛、性能基线、完整迁移演练通过 |
| G 扩展 | 长期记忆、图谱与更多数据连接器 | 相同权限/来源/删除契约测试；证明具体业务收益 |

当前已有文档设计、机器契约、局部关系校验与内部装配内核；阶段B尚未完整通过。后续实现不以接口声明、测试替身或 demo 成功替代真实适配器验证。阶段 C 可用小型参考实现验证治理，但不代表达到多格式和语义召回产品目标。本次逐项结论见 [架构验收报告](ACCEPTANCE_REVIEW.md)。

## 2. 模块替换试验

每次试验保持 REST/MCP 客户端、用户、数据、问题集和业务操作不变，只调整允许的绑定与必要迁移。验收保存旧/新 Manifest、配置摘要、数据快照、测试报告、费用和回退记录。

| 对象 | 实现 A / B | 操作 | 通过条件 |
|---|---|---|---|
| 解析 | DocReader / RAGFlow 解析适配器 | 同一批 PDF/DOCX/XLSX/PPTX/图片重解析 | 结构/表格/定位可比；正文变化生成候选 Revision，不覆盖发布内容 |
| 检索 | WeKnora 复合适配器 / 独立向量+全文流水线 | 标准内容重建索引，配置切换并重启 | 调用兼容、正确过滤、引用不失效；缺少标准内容往返能力则判定复合路线未通过 |
| 模型 | 云供应商 A / B | 替换生成、重排；另试不同维度嵌入 | 输出契约兼容；嵌入切换新代际，旧向量不混用；记录质量/延迟/成本 |
| 文件 | 本地 / S3 兼容 | 复制原件，核对哈希，切换，回退 | BlobRef 和引用稳定、下载鉴权不变、无丢失或错误覆盖 |

其他模块先准备公共契约测试；不要求首版为每个模块维护两套生产实现。数据库替换需单独证明事务语义，不能只通过 CRUD 测试。

## 3. 必须通过的场景

| 编号 | 场景/故障注入 | 必须观察到的结果 |
|---|---|---|
| AUTH-01 | 两个空间同名 KB，猜测对方文档 ID | 检索/读取/下载/历史/反馈均不泄露存在性或内容 |
| AUTH-02 | 机器 Key 携带伪造 user_id，或权限缓存未过期时撤权 | 不能冒充用户；新的访问校验立即拒绝；流按设计终止 |
| PUB-01 | 索引写入失败、准备超时、worker 被杀 | 旧版本可用，新候选不可见；恢复后幂等重试 |
| PUB-02 | 两个不同版本同时发布、旧任务迟到 | CAS 保留正确版本；过期任务不能覆盖新发布 |
| PUB-03 | 搜索候选返回后撤回，或索引删除一直失败 | 复核不返回撤回证据；索引残留不会恢复可见性 |
| PUB-04 | 审核通过后尝试修改内容哈希 | 原 Revision 不可变；新内容必须新草稿、新审批 |
| INDEX-01 | 交换不同维度/预处理模型、只准备部分必需通道 | 拒绝查询或发布；不能切换半成品代际集合 |
| INDEX-02 | 后端上下文扩展包含未授权父块 | 丢弃/拒绝不合法证据；该适配器未通过正式验收 |
| REF-01 | 重分块、存储迁移、索引替换后读取旧 citation | 解析到相同版本和来源；仍执行当前权限与撤回检查 |
| JOB-01 | 重复事件、乱序事件、租约失效的旧 Worker 提交 | 结果不重复；旧状态不覆盖新状态；fencing 拒绝旧 Worker |
| REG-01 | 不兼容主版本、缺少过滤能力、依赖环、健康失败 | 核心服务不就绪；已分配资源释放；错误不泄露凭据 |
| API-01 | 同一主体通过 REST/MCP 调用四项能力 | 相同结果语义、权限、错误和请求追踪；无后端绕行 |
| REFLECT-01 | 无证据、恶意文档指令、超时/循环改写 | 不越权调用工具；最多额外两轮、总预算30秒；不自动发布建议 |
| MIG-01 | 迁移后新增发布/撤回/权限变更再回退 | 新写入经重放或反向迁移保留；撤回内容不复活 |
| REC-01 | 丢失 Redis、恢复数据库和文件备份 | 任务可从事实源恢复；内容/权限/引用一致，明确恢复水位 |
| DRAFT-01 | 解析未完成时编辑草稿或替换附件 | 旧结果不能覆盖较新 row_version，转为独立候选或明确过期 |
| HASH-01 | 不同语言 serializer 处理中文、换行、表格、空值 | 对同一冻结内容得到相同哈希；人工修改改变哈希并要求重新审核 |
| JOURNAL-02 | 两事务按与序号分配相反的顺序提交 | 迁移水位不遗漏迟提交事务，恢复保持整个事务的全部变更 |
| GC-01 | 上传/迁移重试期间执行原件与孤立产物回收 | 保留锁及真实引用阻止误删；窗口结束后的清理可重试且可审计 |
| ROUTE-01 | 关键词/向量分别绑定不同实现，替换其中一路 | 其余调用契约稳定；对应写入/召回代际兼容验证通过 |
| ROUTE-02 | 复制同一混合结果、多个KB重复放大候选预算 | 不重复增加排名贡献；全局候选/并发/时间预算不超限 |
| ROUTE-03 | 必需路线失败、可选图谱失败、索引/召回布局不匹配 | 必需失败拒绝/明确失败；合法可选失败记录降级；布局不匹配拒绝装配 |
| COMPOSITE-01 | 声明整体替换的写入/召回能力组只替换一半 | 装配拒绝，错误明确；完整迁移后成组替换才可进入运行验收 |
| EVIDENCE-01 | 一个Chunk跨多个Block，或混合召回来自多个通道 | 每个外部片段与citation范围对应；内部保留正确代际集合，不能遗漏必需通道 |

测试必须穿透真实后端过滤与一致性行为。单元测试用于状态机和纯算法，集成测试验证存储/引擎，端到端测试验证伙伴调用；测试替身不能证明引擎能力。

并发和迁移补充场景见 [一致性协议第7节](CONSISTENCY.md)。它们覆盖多 KB 嵌入规格、迟到 Worker 的外部写入、授权撤销时序和回退日志，必须与本表共同验收。

## 4. Recall 与回答质量

建立中文评测集，分训练/调参/封存测试三个集合；按来源文档族拆分，避免同一材料变体泄漏。建议首轮至少 300 个可回答问题，覆盖精确事实、同义表达、长文、表格、扫描件、多证据/多跳；另设无答案、越权和撤回问题集合。正式样本数量根据覆盖度和置信区间调整。

每个可回答问题标注允许访问且当前已发布的相关证据单元集合 R(q)，以文档版本+Block 范围表示，避免分块策略变化影响标准答案。返回前10项映射到去重证据集合 H10(q)。

`Recall@10(q) = |R(q) ∩ H10(q)| / |R(q)|`；主指标为问题级宏平均，目标 ≥0.90。一个返回项包含多个片段时按真实覆盖范围匹配，不能简单以命中文档计为命中全部证据。若所需证据超过10个，预先规定聚合证据单元并同时报告原始上限，不删除难题提升分数。

另外报告 Hit@10、MRR/nDCG、各题型 Recall、置信区间、无答案拒答率、引用支持率、回答正确率和越权泄露数。无答案/越权题不混入 Recall 分母，权限泄露必须为0。多跳问题额外报告完整证据链命中率。重排前与重排后分别记录，主指标以最终提供给用户/模型的证据为准。

候选与基线使用同一封存测试集，调参不能查看封存答案。生成质量由盲评抽样和可复核标注衡量，模型自评分只能作为辅助。每份报告包含语料哈希、标注版本、配置摘要、模型确切版本、实现 commit、硬件和并发。

## 5. 延迟与容量

先固定测试条件：CPU/RAM/存储、模型地区、资料总量与分块数、OCR 比例、索引规模、并发、冷/热缓存和测量时长。分别测纯检索 p50/p95/p99、首个有效文本耗时、完整回答耗时、反思总耗时、上传/解析吞吐及每请求费用。缓存命中和未命中不能混成一个成绩。

设计预算：普通检索 p95 ≤2秒、普通回答首个有效文本 p95 ≤5秒作为初始工程目标，须在首轮基准条件中确认；不是当前性能承诺。反思30秒是请求硬上限，不等于成功率保证。负载报告同时给超时率和错误率，不能只统计成功请求。

达到质量门槛后再优化索引、批处理、缓存和并发。如果质量与延迟冲突，提供显式快速/深度 Profile，不能无提示减少权限检查或缩小评测范围。

## 6. 文档评审和实现前检查

- 各模块有责任、端口、数据所有权和替换边界；厂商标识不进入外部引用。
- 发布、撤回、并发、缓存、历史读取和流式响应的权限语义明确。
- 配置不能绕过审核和授权；可选能力不可用时有明确结果。
- 组件已知能力与待试验能力分开；复合实现不计作细粒度替换通过。
- 迁移包含新增写入、删除墓碑和回退边界；存在可执行故障试验。
- 后续生成的 schema/OpenAPI/Go 类型须对照本文逐项审核，而不是以当前测试骨架的字段命名作为既定标准。

文档结构与链接检查只能证明文档完整性。实际架构验收仍需要阶段 B–F 的运行证据。

离线装配语义校验见 [模块装配第9节](MODULE_PROTOCOL.md)，当前使用假设模块验证配置逻辑。它补充Schema结构检查，不能替代真实注册中心、工厂资源回收、健康检查或后端契约试验。

伙伴契约结构校验执行 `python docs/architecture/check_partner_contract.py`。当前通过本地引用、29个Schema、8个DTO样例、4类标准Block、18个非法DTO拒绝、5类SSE载荷及4个operationId校验。该脚本不等同完整OpenAPI规范校验器，未验证HTTP/SSE传输、真实授权、来源对齐、结构化内容语义或MCP SDK行为。

管理契约结构校验执行 `python docs/architecture/check_management_contract.py`：26项操作、64个复用/管理Schema、本地引用、路径参数/幂等头、11个请求样例和7个非法DTO检查通过。完整OpenAPI规范另由第7节校验；响应语义、真实权限、multipart上传、CAS与管理界面端到端证据仍缺失。

## 7. OpenAPI规范校验证据

三份OpenAPI统一使用 [openapi-spec-validator](https://github.com/python-openapi/openapi-spec-validator) 0.9.0进行规范校验，结果见 [文件哈希与报告](evidence/openapi-conformance.json)。伙伴4项、管理26项及远程模块17项操作均通过OpenAPI3.1.1检查；删除必需info字段的对照样例均被拒绝。

因此第6节的两个自有结构脚本仍不等同规范校验器，但独立的规范校验步骤已有证据。响应语义、真实权限、上传、CAS、SSE/MCP运行行为和UI尚无证据。

```powershell

& '.\.local\openapi-review-env\Scripts\python.exe' docs/architecture/check_openapi_conformance.py
```

已存在环境可跳过创建与安装。`--write-report`在成功后刷新报告。依赖版本清单按本次Python3.13/Windows环境保存；其他环境需要验证安装兼容性。报告绑定规范文件SHA-256，后续修改或重生成契约后需重新检查，不把旧PASS用于新文件。

## 8. Go端口编译边界

主要能力与辅助仓储草案共30个Go接口在pkg/contracts，仅依赖标准库。最初单包编译输出`[no test files]`；现已新增ValidateReadyGenerationSet关系校验和测试，复合与独立通道证明通过，16类不一致目标被拒绝。执行 `go test ./pkg/contracts` 和 `go vet ./pkg/contracts` 通过；没有真实适配器测试。

`go test -cover ./pkg/contracts`记录当前可执行代码的语句覆盖率，主要是关系校验器和PublicError方法，不衡量接口声明是否已经实现，更不证明解析/检索/发布覆盖率。后端Verify、元数据权限、审批、CAS、并发与迁移场景仍需单独通过。

2026-10-12完整 `go test -cover ./...` 和 `go vet ./...` 通过，contracts语句覆盖率92.6%，kernel为89.6%。内核覆盖端口替换、预检拒绝、依赖拓扑、启动检查、资源回收、取消、快照副本和严格JSON检查。测试使用假设模块，没有真实解析/检索后端。

内核接收已解析的内部装配计划；正式部署归一化、制品锁、流水线策略和持久化状态核对尚未接入，详见 [内核边界](KERNEL_RUNTIME.md)。全量字段对照、传输映射、状态机和内容/权限/事务边界校验仍在后续阶段，不能把当前包测试提升成产品服务、权限、发布或召回验收通过。

## 统一本地验证入口（Windows）

[check_architecture.py](check_architecture.py)顺序执行全量Go测试（含静态依赖门）、go vet、全部Python架构测试及伙伴/管理/远程模块OpenAPI结构校验。首次使用需已有`.tools/go/bin/go.exe`、当前Python的jsonschema环境，以及第7节的固定版本OpenAPI验证虚拟环境；工具缺失作为失败记录，不自动安装或跳过。

```powershell
python docs/architecture/check_architecture.py
```

默认输出`.local/architecture-check/latest.json`；`--report`可指定保存位置，`--timeout`设置每个命令的秒数。报告保存逐项命令/退出码/输出、UTC记录时间和Go/机器契约输入的SHA-256，并比较运行前后文件库存。任一检查失败、执行超时、工具缺失或输入变化，命令非零退出。后续修改输入必须重新运行，不以旧报告宣称当前通过。

报告明确`production_acceptance=false`；`local_checks_passed=true`只表示列出的本地范围。三份OpenAPI均为结构验证，不证明处理器、认证、供应商语义或SDK行为。运行组件、数据迁移、性能和真实召回门槛不由该入口判定。

本次统一检查通过，Python测试219项；执行器五项测试验证非零退出与诊断、缺失工具及超时不会通过，并覆盖输入新增/删除/变更、二进制样本与依赖锁。当前结果归档见[统一本地检查证据](evidence/unified-local-checks.json)。该命令可作为后续CI入口，但当前部分Python跨语言试验依赖Windows路径，尚未建立跨平台或云CI支持。


输入库存补充：examples/testdata下所有字节文件均纳入哈希，不仅限JSON/文本；OpenAPI固定依赖清单显式纳入。生成证据与缓存排除，避免报告自引用。清单仅声明这些文件的内容身份；工具路径记录不等于工具二进制或已安装传递依赖内容验证，报告显式保留这一限制。
