# 搜索重排与前后证据复核

更新：2026-10-16。实现位于统一 SearchService，三版PG原生运行及独立关系复核通过。

## 执行规则

配置 EnableRerank 后，计划源必须提供标准 Reranker，缺失时拒绝执行，不能静默跳过。重排器由配置绑定的实例解析。未启用时保持普通检索流程；空候选不调用重排器。

顺序为：检索 → 完整当前证据复核 → 重排 → 检查输出仅来自输入 → 再次完整当前证据复核 → 返回。

首次复核在候选传给重排器之前完成，检查当前身份、权限、配置、审核、发布及实际来源。重排受 RerankTimeoutMS 和剩余请求总预算约束；超时或依赖失败时整批拒绝，不返回未经复核的部分结果。它不替代外部模块 Grant、调用账本或数据出境策略。

重排结果只允许排序、筛选和截取输入文本。每项引用必须匹配一个尚未被选取的输入候选，摘录必须是该候选文本的非空子串，排名必须连续且从 1 开始。拒绝未知来源、编造文本、同一个输入候选重复使用、非法排名及超限数量。

返回结果保留原候选的 ChunkID、代际、检索来源和原检索分数；更新排名和摘录。检索分数仍表达原检索算法的含义，不冒充重排模型分数。输出前重新认证授权及复核来源，重排期间撤销凭据时不能返回内容。

## 候选预算与返回数量

启用重排时，召回池使用配置的CandidateLimit；单路由还受该路由CandidateLimit约束，多路由由各路预算累加并受总预算约束。用户Top K只限制重排输出，不再提前截断召回池。所有候选仍须在交付重排器前通过证据复核；不能因最终只返回一条就跳过其他输入的验证。

未启用重排时保留现有直接检索/融合返回数量规则。召回池扩大会增加处理成本，实际并发、延迟和费用仍按固定部署条件验收。

实库用例以中文“文”召回同一已发布原件中的两条索引候选，请求Top 1；受控测试重排器可以从第二条候选中选择并只返回一条。独立复核匹配实际索引行与最终选中的候选，证明数量分层；不据此宣称Recall@10或模型质量达标。

## 当前验证

单元测试覆盖来源与代际保留、筛选/摘录、编造/重复/排名错误拒绝、缺少已配置重排器时拒绝，以及未通过证据复核的内容不能进入重排器。

原生试验使用实际 RS256、数据库授权/配置、已装配 PostgreSQL 检索和原件复核。重排器为受控逆序测试实现，验证正常链路、伪造摘录拒绝和重排中撤销令牌后的最终拒绝。独立复核检查输出顺序、候选来源保留及配置摘要。

测试实现不证明成熟重排模型的准确性、召回收益、费用或速度。生产重排组件及其模块生命周期、网络准入、取消和发送边界仍需验证。
