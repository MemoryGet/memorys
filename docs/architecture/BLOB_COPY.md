# 原件与附件复制、映射切换契约 V1

本规范细化[一致性协议](CONSISTENCY.md)第6节和[导出契约](EXPORT_CONTRACT.md)，补充D-04的文件迁移边界。[Blob复制清单Schema](schemas/blob-copy.v1.schema.json)及本地只读字节校验已提供；真正的复制器、存储适配器、映射事务、重启核对和文件迁移状态机器契约仍待实现。

## 1. 稳定身份与权威库存

文件存储替换只改变物理位置和StorageBinding版本，不改变BlobRef的id/sha256/size/media_type及space归属，也不改变文档、Revision、Block和公开citation。字节改变必须创建新Blob并进入新草稿/审核，不能用迁移覆盖旧原件。

源库存从受信元数据一致快照取得，覆盖所有仍需保留的原件、图片/音频/其他附件、草稿附件、任务/调用/迁移日志使用的外置不可变载荷以及保留锁引用。不仅复制当前发布文档；合法历史、待审核草稿和回退引用同样受保护。元数据ExportManifest的blob/immutable_payload关联必须与库存对照，无法解析的引用拒绝切换。待确认staging上传先终结或隔离，不伪装成已确认Blob。

首版文件替换采用维护窗口：暂停上传确认、新物理绑定、物理清理及所有会新增/替换文件字节的写入；等待在途文件任务达到可恢复终态。权限撤销和紧急撤回继续进行并记录日志，下载与引用读取执行当前访问闸门。不能把blob_writes=paused标签本身当作真实写屏障证明。

源库存记录snapshot_id、journal stream/watermark、源映射快照ID、构建锁和保留锁。目标映射使用独立快照ID与递增的每Blob绑定版本，目标候选不提前对业务可见。source/target mapping ID不是KB索引BackendEpoch，也不是供应商bucket名称。

## 2. 清单及实际字节验证

每项固定entry_id、space_id、标准BlobRef、source_binding_version、target_binding_version和target_binding_ref。所有Blob及entry唯一；独立源库存与清单必须精确覆盖。target_binding_ref是适配器映射仓储的候选逻辑标识，不是外部citation，不允许根据它拼接路径、下载URL或加载凭据。

复制器从当前源绑定读取，在目标attempt/staging命名空间写入不可变对象；长度和原始SHA-256逐项核对后生成候选绑定。不能用ETag、对象名、只检查文件存在或只比较数量替代字节校验。相同hash的不同Blob/space仍保留独立平台身份，去重不得扩大访问范围。

恢复/导入环境逐项核对真实目标绑定指向的对象字节；校验所持对象版本/句柄必须与切换后读取的对象相同。长效公开对象URL不能作为BlobRef或绕过应用下载鉴权。真正的对象版本、权限及删除语义需由本地/S3等适配器公共契约证明。

## 3. 原子切换与回退

```mermaid
flowchart LR
    A[暂停文件写入并建立保留锁] --> B[取得权威库存与源映射]
    B --> C[复制到目标候选命名空间]
    C --> D[逐项验证字节与完整引用]
    D --> E[原子切换有效映射快照]
    E --> F[重启并核对锁与持久映射]
    F --> G[恢复写入并保留旧对象]
    G --> H[窗口结束后另行评估清理]
```

切换事务核验维护闸门、库存/保留引用完整性、Blob/绑定版本、当前墓碑、任务fencing和独立复制报告；原子更新有效StorageBinding映射快照及迁移/审计/outbox/journal。V1要求选定规模能完成映射切换事务，超限则阻止切换，不能分批暴露一半新映射一半未知位置。部署配置与持久映射失配时不接单，不自动回到旧目录。

尚未恢复写入时回退仍需核对权限/撤回和旧对象完整性。恢复写入后，先暂停文件写入，将新Blob、更新映射、删除/撤回墓碑和保留状态通过完整事务日志回放并验证到旧实现，再切回。旧实现不能表示新状态或无法复制新原件时阻止回退，保持当前有效实现或隔离恢复。不能把旧目录重新挂上就宣称新写入已保留。

读取与撤回继续依据当前权威权限/发布事实，物理残留不使内容重新可见。复制中断可幂等恢复，旧对象和未确认候选由保留锁保护；结果未知的目标写入/删除保留调用账本和墓碑，不盲目覆盖当前有效绑定。窗口结束仍按[回收闸门](RETENTION_CONTRACT.md)检查真实引用和未知任务，不能只按清单时间删除旧目录。

此流程是设计约束，文件迁移状态记录、绑定集合仓储与切换事务没有运行实现。

## 4. 当前离线证据

```powershell
python docs/architecture/build_blob_copy_contract.py
python -m unittest discover -s docs/architecture -p test_blob_copy.py
```

`blob_copy_validation.validate_copy`读取操作者显式指定的本地文件映射，从不按清单字符串打开路径、不下载、不复制、不删除、不切换绑定。它与独立源库存比较平台身份、space、摘要、长度、媒体类型和源版本，再分块计算目标字节摘要，并检查读取期间可观察的文件身份/大小/修改时间变化。单次离线最多10000对象、默认总256MiB可显式调整；这不是生产企业容量上限。

本地文件在校验后仍可能被修改，因此成功不构成不可变对象或实际目标绑定证明，固定ready_for_binding_cutover=false。可信库存/保留锁、目标版本句柄、上传与GC屏障、当前权限/墓碑、原子映射、重启及回退新增字节均列为未验证。

专项试验使用真实临时文件：正确字节、空文件/空库存、8MiB流式读取、同长度篡改、截断、库存漏项/重复、跨空间/身份/类型改变、版本失配、独立快照失配、精确整数、预算及模拟读取期间文件变化。它不证明S3或本地生产适配器已经实现，D-04保持开放。
