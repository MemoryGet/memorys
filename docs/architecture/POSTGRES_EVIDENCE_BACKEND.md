# PostgreSQL 当前证据复核后端

2026-10-16：默认实现已通过当前范围的实库验证；完整生产验收保持开放。

`postgres.EvidenceBackend` 实现标准 `queryread.CurrentBackend`，由 `CheckCurrent` 调用。身份、当前授权/配置控制源与证据后端分别注入；默认后端复用QueryReadUnit、FrozenContentReader、BlobStore、独立原件读取控制及文本投影策略。业务调用不引用SQL事务或供应商类型。

## 核验顺序

1. 固定调用方已观察的发布/审核事实与Evidence，另开只读主库快照，核对当前有效版本、发布epoch、后端代际、批准和当前审核规则。
2. 从实际原生准备产物及真实关键词索引读取完整快照，核对产物摘要、快照校验值、所属及删除状态。Evidence引用须匹配实际索引记录，摘录须存在于该记录的正文中。
3. 释放数据库事务连接后，新读取类型化Revision及标准冻结正文，核对双摘要。版本文本引用走既有正文定位核验；original/coarse引用还核对批准块/锚点、独立读取权限、实际原件字节及文本投影。
4. 内容和原件处理完成后，再开新的主库观察点重做发布及实际索引核验。原件投影期间发生索引删除时，不能沿用第一次Ready检查。
5. 返回外层CheckCurrent，继续最终身份、范围、配置和规则刷新。该顺序是多个观察点，不是网络发送与跨系统撤权的原子屏障。

读取实际索引的公共内部函数也用于关键词Retriever，防止检索和输出检查采用不同的完整性规则。

## 当前支持与边界

默认实现只支持原生单关键词渠道的已发布代际；向量、图谱和复合渠道不能仅凭声明Ready通过。一个批次最多1000个文档和1000条Evidence，单次索引扫描最多10000条记录、16 MiB，核验前后各一次。原件读取在整个批次累计最多16 MiB，计入投影后的第二次完整读取；每个原件最多8 MiB。正文及任务仍受既有大小、Scope过期和父请求期限限制。生产规模性能尚未验收。

UTF-8文本/Markdown原件的粗粒度引用已有本地实现；PDF、Office、OCR与精确页码/表格/媒体定位仍待接入并验收。人工编辑正文应使用与实际来源相符的版本引用或派生来源；核验器不会改写SourceKind，当前派生引用的完整处理也待补齐。

生产CurrentControl、真实IAM/RLS、模块部署装配、远程调用授权及最终模型/REST/MCP输出尚未完成。实库控制源使用测试主体和策略替身，并读取真实数据库审核规则，不构成真实用户授权证明。

## 实库验证设计

保留人工编辑来源不匹配的拒绝案例，另以真实原件内容创建新草稿，经实际提交、审核、索引准备/完成及最终发布，作为正向数据。原件目录在整条嵌套验证结束后清理。

运行场景覆盖完整CheckCurrent、真实索引/冻结正文/原件摘录、错误索引引用/摘录、人工编辑不能冒充原件、独立原件读取拒权、最终控制撤权、投影期间真实删除索引，以及撤回/撤销批准后拒绝旧观察。已实库复现并修复逻辑分块删除但物理行仍在时可被旧完整性检查接受的问题。公共索引读取器现在拒绝包含分块删除标记的代际，检索和证据复核均已验证；测试同时确认物理行仍保留。

## 当前证据

同一479项输入与同一Go探针在PG15.19/16.15/18.6各通过184项累计检查，其中11项为当前证据后端场景。[独立运行复核](evidence/evidence-backend-runtime-review.json)核对3组实际完整CheckCurrent样本、真实索引记录/批准块/原件摘录关系和逻辑分块围栏保留行。12份标准冻结正文、3个实际关键词候选及51条样本索引记录的既有独立复核同步通过。

Go全量测试/vet、227项Python及三份OpenAPI通过。PG私有目录和测试端口清理已另行核对；原件目录由探针在嵌套验证结束后删除并检查。见[版本矩阵](POSTGRES_VERSION_MATRIX.md)。生产控制源、正式模块配置装配与最终输出仍未验收，不关闭完整CHECK/Recall/迁移门槛。
