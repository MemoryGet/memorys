# 检索协调器：跨知识库预算与失败语义

本设计补齐ROUTE-02，衔接[模块协议](MODULE_PROTOCOL.md)、[融合契约](FUSION_CONTRACT.md)及[检索评测](RETRIEVAL_EVALUATION.md)。查询应用拥有计划与执行顺序，Retriever/Fuser是可替换端口。当前已有配额规划、跨库交错合并和固定工作池的局部运行证据；真实授权/发布及后端调用链尚未贯通。

## 1. 固定输入与职责

应用先验证主体和当前权限，取得不可变Pipeline/QueryProfile及QuerySnapshot。每条路线的目标库存必须从当前允许的KB、已发布版本、有效BackendEpoch/GenerationSet交集产生，并完成通道/嵌入规格/后端布局核对。库存是受信输入，不允许客户端提供路线、实例、代际或授权列表。

一次调用只使用一个KB及一个有效epoch，其PublicationFilter、Scope、GenerationIDs必须收窄到该目标。不同KB不得混用knowledge_ids或供应商内部ID。没有可查询的已发布代际时，库存明确为空；数据库故障、权限检查失败或未知发布状态不能解释为空。

数据面端口保持RetrieveRequest/FuseRequest不变。协调器不持有供应商客户端：通过已装配Retriever或CompositeEngine调用Search，使用同一个Fuser端口。端口替换须通过过滤、来源、取消及预算契约；声明特性不能代替运行验证。

## 2. 准入与配额

首版分库调用策略使用每条路线已声明candidate_limit。将目标按平台KB ID排序，路线预算L、目标数N时，每个目标获得floor(L/N)，前L mod N个目标各增加1。所有目标至少获得1；N>L直接拒绝本轮计划，返回明确的查询范围/预算不匹配错误。不能静默跳过KB、自动提高Profile预算或每个KB各取完整L。用户可选择缩小范围，管理员可建立更高预算的新Profile版本。

每条路线所有子请求Limit之和等于路线预算；各路线预算之和不超过QueryPolicy.candidate_limit。零目标路线保留，产生显式空列表，不发后端请求。预算不因其他路线无结果而借用，不因重复交付或提前返回而增加。均匀配额可能降低跨库召回，是可观察的取舍，必须在同一封存评测集检查后才能接受。

主机还提供独立MaxCalls与MaxParallel准入限制：MaxCalls为1–256，MaxParallel为1–32且不超过MaxCalls；实际路线×KB调用数超过MaxCalls则拒绝。纯规划器仅记录MaxParallel，执行器必须使用有界队列/工作池，不能为所有目标立即启动goroutine再等待限流。队列等待也计入同一父deadline。后续若改变配额策略，须版本化配置及重做效果比较。

## 3. 单路线跨库排名

不同KB的分数统计通常不同，首版不依据原始score直接排序。分库结果先分别验证严格递增rank、目标KB/epoch/代际/路线/实例、Limit、来源与正文等契约，再按排序后的KB固定轮询交错：依次取每库第1项，再每库第2项，跳过已耗尽列表。赋予该路线连续全局rank，最多路线预算L。原始子请求rank/KB及配额存入内部追踪记录，供应商分数仅作诊断。

交错是一项明确的路线合并策略，不声称得到全库语义相关性排序。其结果是一份RankedList；多个KB不能成为多个新RouteID，复合混合召回也不能拆成两路重复投票。之后各真实路线仅贡献一次RRF，再独立重排。重复子请求交付按调用身份拒绝或幂等处理，不能补充候选预算。

若未来某适配器支持同一评分空间下的一次多KB查询及前置权限过滤，可建立新策略版本，通过共同契约后替换此合并策略；不能仅宣称分数可比较便改变当前排序。当前Merge已实现交错合并及PartitionOrigin内部局部追踪记录；持久观测与真实调用链尚未实现。

## 4. 失败、降级与二次检查

| 情况 | 本轮行为 |
|---|---|
| 身份/当前权限/发布快照获取或返回前复核失败 | 整请求终止，无证据或回答输出 |
| 候选越权、草稿/撤回、错误KB/代际/来源或非法DTO | 整请求终止，记录静态错误及受控审计；不得当作可选降级 |
| 必需路线任一分库调用超时/不可用 | 整轮失败；不将未完成路线伪装为空结果 |
| 可选路线任一分库调用超时/不可用 | 整条路线丢弃，记录明确降级原因和失败目标；其余成功路线继续 |
| 某目标成功返回零候选 | 正常空列表，保留成功状态 |
| 所有路线成功但没有足够证据 | 返回证据不足；允许按既定反思预算改写后重试 |
| 主请求取消或总deadline到期 | 取消排队和已执行调用，整请求停止；不再启动后续阶段 |

可选路线整条丢弃使降级规则不依赖失败KB的顺序；保留半条路线会改变其配额/排名语义，首版禁止。降级元数据与无结果状态分别记录，不能以缺席列表推断原因。重试仅限预算内明确允许的可重试错误，不重试权限/契约失败；不能将一条路线的失败调用重新包装成新路线贡献。

每轮开始前及返回证据/向模型发送正文前执行当前发布与权限检查。检查失败时，即使缓存、历史引用或原Snapshot允许也不得输出。反思最多额外两轮，总预算30秒；排队、嵌入、检索、融合、重排与生成均分享父预算，各阶段超时取父剩余时间和Profile阶段上限中的更小者。

## 5. 可执行规划器及剩余验收

`pkg/retrievalplan.Build`接收QueryProfile、逐路线明确库存及主机Limits，返回独立Plan值；捕获Query ID/版本/摘要、排序路线/KB、有限子请求配额和required标记。验证重复/未知/缺失路线、KB重复、空epoch、预算和扇出上限。它只做结构准入，不重算完整Profile摘要、不验证权限、发布或后端布局，也不执行调用、限制实际并发或合并排名。

5项Go检查验证预算和顺序稳定、拒绝不可能配额/扇出、拒绝非法库存、显式空路线、输入修改隔离及Profile/主机上限。见[执行证据](evidence/retrieval-plan-review.json)。完整协调器需继续通过下列运行门槛，当前均未取得证据：

| 门槛 | 必须取得的运行证据 |
|---|---|
| COORD-01 库存可信与过滤 | 真实授权/发布仓储产生收窄子请求；非法目标不可被计划或返回 |
| COORD-02 并发与截止 | 实际工作池峰值不超过MaxParallel，排队到期不启动调用，取消释放资源 |
| COORD-03 排名与去重 | 多库不同分数尺度合并符合固定交错；不增加路线票数，乱序交付结果稳定 |
| COORD-04 故障与降级 | 逐个必需/可选子调用故障；必需终止、可选整路线丢弃、零结果状态区分 |
| COORD-05 当前状态与引用 | 调用期间撤回/权限变化均阻止输出，所有来源可追溯且代际匹配 |
| COORD-06 效果与替换 | 同一中文封存集验证配额策略、真实两后端接口替换及Recall/延迟/费用 |

本次推进跨KB规划和设计，不关闭ROUTE-02、契约冻结、完整服务或Recall@10≥90%目标。

## 6. 合并实现与局部证据

`pkg/retrievalplan.Merge(ctx, route, results)`在同一端口前处理成功分区：路线/实例一致、调用配额之和等于路线预算、每KB唯一、结果库存完整且不重复。结果的目标KB与epoch字段匹配计划，候选KB/路线/实例匹配调用；原rank严格递增且最多1000，分数有限，来源平台ID及代际ID非空，原始候选不能携带FusionOrigins。未知、缺失、重复、超额或非法结果返回零输出及静态ErrInvalid。

结果按计划KB排序后交错，重写连续全局rank；原始score不参与比较，保留诊断值。每项内部Origins记录目标、原rank和全局rank。候选与嵌套citation/切片通过Go JSON复制，输入后续修改不改变输出；序列化输入总量限制16MiB。调用方须预先验证来源DTO大小、深度和语义，合并内部的JSON/排序不能硬抢占，只在循环及返回检查context取消，不能据此声称硬实时预算。

epoch匹配只是返回包络与计划相符，不证明后端实际查询了该epoch；GenerationIDs只检查基本字段，不证明它们属于已发布GenerationSet。来源位置、正文真实性、当前授权及发布仍须上游验证和返回前复核。结果必须是完整成功列表；可选路线故障由下述Execute执行器分类处理，不能以缺失结果调用Merge作降级。

6项Go检查覆盖稳定交错/乱序到达、嵌套副本、实际RRF单路线票数、缺失/重复/错epoch/超额结果、非法候选字段、rank顺序/无穷分数/16MiB预算、显式空结果与取消。见[执行证据](evidence/retrieval-merge-review.json)。COORD-03只取得合成结果算法证据，真实服务/重复调用交付与追踪持久化仍待验；其他COORD门槛、ROUTE-02及总体状态不因此关闭。

## 7. 固定工作池与故障分类

`pkg/retrievalplan.Execute(ctx, plan, SearchFunc)`捕获路线/子调用值，预检路线唯一、配额、库存、计划携带的部署MaxCalls及256调用硬上限；要求父context有deadline。只创建最多MaxParallel个工作goroutine，它们逐项取队列，不为每个KB创建等待goroutine。出队及调用前检查取消，结果校验/复制后才纳入合并，全部工作退出后再返回。

SearchFunc由受控应用适配器提供，负责绑定真正Retriever/CompositeEngine、收窄Request/Scope/Publication、传递有限deadline和核验来源。这里没有接受任意客户端回调。返回数据的所有权须转移给执行器，不能在返回后并发改写。每个成功调用先经Merge单分区校验/复制，保留原rank，再执行整路线合并。

只有受信适配器显式返回ErrUnavailable或最多16层的单原因包装链，才允许可选路线降级；多原因/Join错误一律不能据此降级。该哨兵仅用于传输超时/不可用；身份、权限、发布、来源及DTO失败不得包装为它。可选失败路线的全部成功结果丢弃，未开始子调用跳过，已执行同路线调用继续遵守父取消；记录实际失败目标，不将跳过目标假称失败。必需失败、普通错误、候选校验失败及panic均终止并取消父派生context，返回静态ErrInvalid和零Execution；不回显供应商私密错误。主context取消/截止优先返回其错误，不降级。

工作池等待已启动回调退出，保证正常返回后没有后台遗留调用；这是合作取消协议。忽略context的回调可阻止返回，Go不能安全强杀它；真实HTTP/gRPC/模型适配器仍需通过截止/Body关闭/连接释放试验才能接入。检查与调用之间存在调度间隙，执行器不能承诺在墙钟deadline之后绝无函数进入；已取消context传递给回调，回调自身必须再次检查且不开始网络I/O。纯JSON处理也无硬抢占。固定池不是完整硬实时证明。

6项Go检查覆盖真实同步工作池峰值/全部join、可选路线已有成功后故障整路线丢弃、必需与契约/panic失败、取消后排队调用不启动、deadline不降级且零输出、非法Plan预检。全Go回归和vet通过，见[执行证据](evidence/retrieval-executor-review.json)。COORD-02/04仅受控回调运行证据，不代表真实后端取消、权限/发布和Recall效果通过；完整应用、返回前复核和真实替换仍待实施。

## 8. 跨路线字节预算与混合错误修正

复核发现原Execute只有每调用/每路线16MiB限制，多个合法路线合计可超额。当前MergeResult额外报告EncodedBytes，按实际Go JSON原始候选长度计数；Execute以互斥账本累计所有成功校验分区成本，追加每候选3字节的全局rank位数余量，整轮最多16MiB。即使可选路线随后降级，已处理数据不退还预算。超额立即成为契约失败、取消其他工作，返回零Execution，不能借可选降级绕过总预算。

该数值是候选序列化处理预算，包含引用和代际字段；不代表进程峰值内存。回调已返回的输入与正在复制的多个分区可能同时存在，JSON序列化还需临时空间；外围传输/DTO应先限制响应体、嵌套和每候选大小。未验证真实网络/内存压力或费用，不把本地上限作为容量承诺。预算是每轮，反思多轮仍须另外受总时间/调用费用策略约束。

原错误分类使用errors.Is，因此errors.Join(ErrUnavailable, ErrInvalid)会令可选契约失败被降级。现在只接受明确哨兵或有界单Unwrap链，多Unwrap/Join一律按失败终止。单包装的传输异常仍可降级。错误来源须是受控适配器；这一结构检查无法判断某适配器是否错误地把权限问题标记成传输问题。

新增3项Go回归：多路线分别低于16MiB但合计超额返回零输出；可选混合传输/契约错误不可降级；单包装传输错误仍可降级。两项缺口已在修复前重现，修复后全Go测试与vet通过。见[复核证据](evidence/retrieval-budget-review.json)。这补强COORD-02/04局部约束，真实授权/发布、后端资源、容量与Recall仍待验。

## 9. 部署准入限制完整传递

原Build虽然核验MaxCalls，但Plan仅保存MaxParallel，Execute只能检查256的固定硬上限。当前Plan增加MaxCalls并捕获Build传入的部署值；执行前核对1–256范围、MaxParallel不超过MaxCalls，并核验全部子调用数不超过该值。任何不满足条件的计划在启动工作池前拒绝，不能等到调用过程中才发现超额。

Plan仍是平台内部值，不作为REST/MCP请求字段接收；用户不能选择更高的调用上限。可信配置归一化提供Limits，应用按请求冻结该版本再规划；MaxCalls字段结构校验不证明配置来源，也不能阻止受信代码自身错误地增加它。跨进程计划若未来需要传输，须另定义版本化协议、可信配置引用及完整预算绑定，不直接序列化内部Go struct作为正式远程契约。

新增3项Go检查：低于计划调用数或非法上限预检时零调用；正好达到部署上限允许执行且修改原Limits不影响计划；并发大于调用上限拒绝。全Go测试及vet通过，见[复核证据](evidence/retrieval-call-cap-review.json)。这补齐内部预算传递，未证明正式配置加载/真实性、跨进程计划或真实后端验收。

Call到RetrieveRequest的权威准备与重新绑定见[分库请求与授权边界](PARTITION_REQUEST.md)。该设计不等同于已实现子授权或发布投影服务。
