# 本地工作台后续路线图

当前本地工作台已经具备导入、编辑、审核、发布、撤回、删除清理、原件预览、结构化定位、OCR/转写、关键词/语义/混合检索、多知识库关键词联邦检索、流式问答、标签、来源反馈、任务事件、审计和指标面板。标签已支持列表内批量添加/移除，并在单次 manifest 写入前完成逐文档授权检查。下面是适合继续推进的功能，按交付风险和用户收益排序。

## P0：先补齐可交付性

1. **完整验证环境**：在安装 Go 工具链的环境运行 `go test ./...`、`go vet ./...`，并设置 `MEMORYS_LOCAL_TEST_DATABASE_URL` 运行真实 PostgreSQL 生命周期测试。
2. **媒体验收样本**：准备含文字图片、扫描 PDF、带时间段的 WAV/MP3/M4A 样本，验证 Tesseract/whisper worker 的失败、超时、取消、重启恢复和引用定位。
3. **跨重启恢复**：发布和删除清理任务已有租约/fencing 边界；本地解析任务现在保存状态、输入和 row version，重启会标为可重试失败；PostgreSQL 解析 Worker 现在能对准备失败做 fenced failed 回写，并可由 Redis task ID 触发、无消息时回退 queued 扫描。仍需用真实数据库和后台进程验证崩溃接管、未知提交和重启恢复。
4. **本地数据备份与恢复**：已由 `tools/local_backup.py` 提供数据库、完整状态目录、原件、反馈、审计、任务状态和构建产物的一致性备份、校验与新目录/新数据库恢复；后续只需继续覆盖跨版本和在线不停写场景。

## P1：提升日常使用效率

1. **标签管理深化**：批量添加/移除和大小写归一化已完成；文档列表已支持服务端标签筛选并将条件绑定到游标；继续增加标签建议、按标签统计。
2. **反馈闭环**：本地反馈已保存触发问题并可导出“问题—引用—评价”样本；继续支持按文档/版本/标签生成评测集草稿，并在反馈处理后记录关联的修订或重新发布任务。
3. **检索评测**：保存脱敏查询、命中来源和用户反馈，提供 Recall@K、引用准确率、有帮助率和延迟趋势的本地报告。
4. **定位体验**：证据卡片已可按发布版本打开/下载原件，PDF 页码会带入浏览器跳转片段，OCR 已保留页级平均置信度，音频 segment 已保留起止毫秒；继续补 OCR 页图、音频播放器联动，以及 PDF/Office 精确定位的可视化高亮和原件打开失败提示。
5. **任务中心**：SSE 已支持 `Last-Event-ID` 续号和完整快照重连；管理和本地任务列表现已支持按类型、状态、文档和创建时间范围筛选，游标绑定全部筛选条件。
6. **访问与配置**：增加本地会话过期提醒、端口/目录配置校验、解析器和模型依赖的一键诊断报告。

## P2：扩展能力边界

1. **更多输入源**：邮件、网页、ZIP 批量导入以及云盘连接器，统一复用当前摘要校验和审核流程。
2. **更丰富的内容结构**：代码、JSON、Markdown 表格、图片说明和音频说话人标注，保留可验证的来源边界。
3. **可选的持久化反馈库**：在单机 JSON 之外提供 PostgreSQL 存储和导出迁移，支持多用户或多工作区场景。
4. **性能控制台**：展示索引构建、向量缓存、解析耗时和内存上限，支持按能力关闭或降级并保留降级原因。

MCP 搜索和当前发布正文读取入口已在启用认证 PostgreSQL 搜索时接入服务器；`knowledge_ask`、`knowledge_feedback` 的严格伙伴/MCP 传输适配器已补齐，但仍需装配生产问答/反馈应用服务后开放；不能用本地 JSON 反馈存储冒充多用户服务。

多知识库关键词分片已完成，但语义/混合检索、伙伴问答仍需在协调器层接入同一分片策略。路线图中的 P0 项完成后，再把 P1 的反馈和检索评测数据作为下一轮模型、分块和重排优化的验收依据。

本地 runtime 现在允许启用 `Query.Policy.EnableRerank`，默认装配有界 `knowledge.LexicalReranker`；宿主启动时可用 `Search.WithReranker` 注入模型服务，当前仍需真实模型和 Recall@10 验收。
