# 受控构建锁与部署核对契约 V1

本规范细化[模块装配协议](MODULE_PROTOCOL.md)的BuildLock，是D-04的部分交付。[锁文件Schema](schemas/build-lock.v1.schema.json)和[离线检查入口](check_build_lock.py)已提供；正式部署归一化、持久化代际读取和运行模块认证仍未完成。

## 1. 锁定对象与摘要边界

`lock_id`是不可变平台标识，部署文件的`build_lock_ref`引用该标识，不是下载地址或路径。锁文件保存完整部署文件、各模块清单、各制品与保留策略文件的原始字节SHA-256。摘要不使用JSON重序列化；空白修改也要求新锁。部署文件只保存锁ID，锁文件保存部署摘要，避免双向哈希循环。

每个`provider + implementation_version`在锁文件中恰好一项；同一实现可由多个实例复用。部署所用实现、提供的清单、锁条目与本地制品输入必须精确覆盖，不接受缺失、额外或重复条目。清单摘要覆盖业务能力/特性/配置Schema和依赖声明，生命周期契约另显式核对。源码固定为完整Git SHA-1/SHA-256 revision，不接受分支或浮动标签；源码仓库文本仅用于审计，不触发网络访问。

制品可为Go单体可执行文件或受控适配器制品；同一单体内多个provider可以共享制品摘要，但各provider必须有独立清单并在运行时核对注册表。离线检查只对指定本地文件流式计算摘要，不执行文件，也不证明该文件与所声明源码的构建关系。容器或远程模块后续必须核对实际运行镜像/服务制品摘要及固定后端依赖，不能仅比较一个本地替代文件。

保留策略记录`policy_id + policy_version + file_sha256`，并运行[期限关系检查](RETENTION_CONTRACT.md)。普通settings和锁文件均不能保存密钥正文；凭据引用与确切版本由后续配置归一化及凭据解析器验证，离线文件一致不代表密钥可用。

## 2. 正式启动核对规则

1. 从部署管理的可信、只读制品目录取得锁及其信任证明。用户请求不能提供锁、路径或下载地址。仅有相互匹配的SHA-256不能证明发布者可信，签名/受控构建证明与分发治理仍须实现。
2. 按配置/清单/锁/策略原始字节核对；进入进程后使用同一已核对的不可变输入快照。离线命令发现多次读取期间摘要变化会拒绝；正式运行不能重新打开可变路径执行另一份文件。
3. 归一化为内部装配计划，验证端口/特性/复合组/依赖/策略，并核对运行注册表、制品和外部后端依赖版本。
4. 从权威元数据读取各KB的`active_backend_epoch_id`及其冻结IndexProfile、路由与布局摘要。声明索引绑定必须对应持久化epoch。缺少记录、配置失配、迁移处于未决切换或数据库不可读时不接单，不能自动使用旧索引。
5. 查询策略变化可生成新QueryProfile；索引策略变化必须创建新BackendEpoch并完成迁移。启动命令不能通过覆盖持久化记录“修复”失配。
6. 工厂、健康、凭据、权限与能力认证完成后才发布RuntimeSnapshot。候选新锁保留独立标识；回退重新核对旧锁、回放水位与当前数据，不能只把配置文件恢复成旧版。

步骤4必须在后续持久化仓储及归一化实现中验证，当前离线检查不访问数据库。

## 3. 离线命令与验证范围

```powershell
python docs/architecture/check_build_lock.py --config <部署JSON> --manifest <模块清单JSON> --lock <锁JSON> --retention <保留策略JSON> --artifact <provider> <version> <本地制品路径>
```

多个清单或制品重复相应参数；JSON输入沿用4MiB/64层、重复键及非有限数值拒绝规则，制品用分块读取。所有文件由操作者显式指定，命令不会按锁中的仓库文本或其他字符串下载/打开制品。成功结果固定`ready_for_service=false`，未验证列表继续包括来源信任、构建证明、实际运行制品、外部依赖、持久化epoch和权限等门槛。错误只输出安全类别，不回显配置正文或路径。

`test_build_lock.py`使用临时合成制品验证字节篡改、条目覆盖、生命周期/策略版本、锁ID、浮动源码和安全错误拒绝路径。该制品没有实现模块能力；测试不证明启动、持久状态或真实组件替换成功。D-04的[导出清单](EXPORT_CONTRACT.md)、[日志链](JOURNAL_PROTOCOL.md)、[KB状态机](MIGRATION_STATE.md)及[文件字节清单](BLOB_COPY.md)已另提供局部机器契约；完整typed载荷、数据库/文件状态与正式运行核对仍待完成。

## 信任配置与构建锁的扩展边界（2026-10-13）

详见[信任激活协议](KEY_TRUST_ACTIVATION.md)。记录TrustDomain/Head、不可变快照、KeyRetirement与激活操作的归属，禁止低版本回退及受损公钥换kid复活；历史恢复必须核对备份之外的受信控制面锚点。现有仓储/BuildLock尚未包含完整机器绑定，也无持久激活/分发证据，后续须补齐。

元数据读写数据集与活跃存储代际的运行核对见[存储绑定](METADATA_STORE_BINDING.md)。构建锁的配置/制品字节一致，不等于端点读取的是当前权威数据；动态激活期望由独立控制面验证。
