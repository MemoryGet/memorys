# PostgreSQL 查询权威读层

状态：默认适配器及实库探针已通过当前实现范围的验证。本页描述元数据读取能力，不代表正式检索、当前证据输出复核或真实 IAM 已验收。

## 模块边界

`postgres.QueryReads` 实现平台的 `contracts.QueryReadUnit`，上层仅依赖标准 `QueryReadRepository`。数据库事务、快照字符串和 SQL 类型不进入业务契约；其他仓储可以实现相同接口。

每次 `WithinRead` 使用主库只读 Repeatable Read 事务，在同一个观察点读取发布头、当前审核与策略、后端代际及正式发布记录。回调句柄在退出时关闭；返回对象独立复制。回调结果应暂存，仅在整个 `WithinRead` 成功后使用。

## 当前发布集合

当前默认实现只接纳经过本平台原子最终发布流程的内容。文档的有效 Revision、GenerationSet 和发布 epoch 必须与正式发布历史、准备产物、当前批准及后端代际相符。缺少可核实来源的旧记录不进入清单；数据损坏、仓储或权限校验失败返回错误。

已撤回的文档仍可返回当前文档状态，但不会进入可检索发布清单。撤销批准或当前审核策略不再接纳旧决定时，同样排除该来源。

这里检查准备产物的元数据及摘要，不能证明索引内容仍然存在。实际检索器和输出前复核必须独立检查真实索引效果、引用、当前授权和正文来源。

## 一致性、分页及资源限制

- 同一回调的多页结果保持同一快照；期间提交的撤回在新回调中可见。
- 游标为服务端保存的随机标识，绑定当前读身份、所选知识库和文档排序；跨回调不可重用。
- 默认实现最多扫描当前授权范围内 1000 个有效发布头；超限明确拒绝，不截断清单。状态缓存和单个返回对象分别受 4 MiB 限制，游标最多 1000 个。
- 每次入口和读取操作、回调结束及最终返回前调用注入的当前权限验证器。生产身份及授权提供者仍需另行实现。
- Context 必须带截止时间，预算进一步限制到 Scope 的过期时间。

这不是跨数据库与网络发送的撤销屏障；旧快照不能充当最终输出授权。实时复核必须另开读取。

## 部署身份与兼容处理

`query_store_head` 保存数据库实例的 StoreEpochID 和递增版本。首次部署必须显式初始化；没有记录时拒绝读取。恢复或替换权威仓储后，部署控制应生成新的平台 epoch 并递增版本；数据库内记录不能独自证明防回滚。

回调完成并释放事务连接后，再从新观察点核对 store head；期间 epoch 或版本变化会使读取失败。这也避免最终核对额外占用连接而阻塞单连接池。

后端不可变定义新增 `Number` 和 `CutoverWatermark`，分别表示实际后端代际号和切换水位；不能用配置头的 RowVersion 冒充代际号。缺少字段的旧定义必须经部署迁移创建合格的新不可变定义并显式切换，禁止原地篡改历史定义。

实库探针覆盖原生发布来源、分页期间真实撤回、新读取拒绝旧来源、实际撤销批准、回调关闭、游标隔离、对象复制、权限撤销、取消和 store epoch 轮换。授权验证器仍为测试替身。
