# 模块装配内核与生产接入边界

更新：2026-10-12。规范入口见 [模块协议](MODULE_PROTOCOL.md)。实现见 [内核类型](../../pkg/kernel/types.go)、[预检](../../pkg/kernel/preflight.go) 和 [生命周期](../../pkg/kernel/runtime.go)。

## 1. 两级配置与单一业务契约

```text
正式 deployment-config + 模块清单 + 制品锁
    ↓ 严格结构校验、能力与策略校验、持久化状态核对
部署归一化器（待实现）
    ├─ 部署级内核 Config + 固定 Factory 目录
    └─ 不可变 PipelineProfile 与请求/任务快照
    ↓
kernel.Build → Runtime → 应用服务 → 标准业务端口
```

正式部署格式以 [部署 Schema](schemas/deployment-config.v1.schema.json) 为准，可先运行 [文件级离线检查](MODULE_PROTOCOL.md#10-文件级离线配置检查入口)。`kernel.Config` 是进程内已解析装配计划，采用 version/modules/bindings；不能直接作为正式部署文件。`kernel.Load` 只用于内部计划诊断，不验证索引路线、查询预算、事务组合、复合组或迁移状态。

归一化器必须先验证整个部署，再调用 Build；任何失败不得启动业务入口。流水线可以有多个同能力实例，内部部署级 bindings 只选择默认实例。后续归一化器需生成经验证的流水线实例引用；不能用全局默认绑定覆盖空间/知识库配置。

外部清单采用主版本.次版本契约号。内部内核兼容早期测试中的 `1.0.0`，仅允许零补丁；这一兼容不扩展正式清单 Schema。内部单一目录版本可省略选择，装配摘要会锁定实际版本；正式部署仍必须显式固定实现版本及制品摘要。

## 2. 受控目录与依赖注入

Factory 由受控 Go 构建注册，不在运行时加载任意源码、动态库或网络模块。清单声明能力、版本、能力特性及依赖槽。平台能力映射至强类型端口；服务集合不能缺失、额外声明或返回 typed nil。

当前内核按以下顺序装配：

1. 复制输入，校验实例唯一性、版本、设置、必需能力和绑定。
2. 解析 dependency_slot，检查能力/契约/特性，拒绝未声明的槽。
3. 拓扑排序，拒绝依赖环；验证完成前不调用 Create。
4. 顺序创建并健康检查；依赖只能从已经就绪的实例取得。
5. 生成只读快照与配置摘要，全部就绪后才返回 Runtime。

`Resolve[T]` 将平台能力转换为强类型业务端口。启动装配层的 `any` 不向领域对象传播厂商类型。复合实现可以同时提供多个端口，但是否能拆分仍以复合组约束与真实适配试验判断。

配置对象限制为 4 MiB，嵌套最多 64 层，拒绝未知计划字段、重复 JSON 键、非对象根和尾随数据。直接传入 Build 的模块 settings 同样检查重复键，不能绕过 Load。Factory.Validate 负责自身严格设置 Schema，必须是纯本地、无网络的有界校验；制品 Schema 与引用边界仍需部署归一化器审核。

## 3. 生命周期与故障处理

Create 和 Health 各有 5 秒协调超时。Create 的 context 仅用于初始化，工厂不能把它作为实例后台任务的长期 context。后台任务由实例自有生命周期管理，在 Close 中停止。

成功或部分创建返回的 Instance 由内核回收；工厂未返回的局部资源由工厂自行回收。取消后迟到返回的实例也会进入回收。Create/Health 的 panic 转为安全错误，不在调用结果中泄露原始凭据或配置正文。

Close 使后续 Resolve/Get 失败，按逆依赖顺序回收；单个回收失败仍继续其他实例。每个 Close 有独立 5 秒预算，并从取消的业务 context 中脱离以完成清理。总回收时间可能达到实例数乘以 5 秒，部署停机预算必须与此匹配。重复关闭等待首次回收结果。

应用必须先停止接入并排空进行中的请求，再关闭内核；内核不能撤销已经交给调用方的端口引用。工厂必须返回独立实例，或自行正确管理共享资源引用计数。

Go 无法强制终止不响应 context 的回调 goroutine。超时限制协调等待，不能保证任意失控适配器已停止。适配器契约测试必须验证取消、后台任务和资源关闭；无法保证进程内取消的组件使用独立进程适配，并由进程管理器执行退出与终止。

## 4. 配置摘要与凭据

装配时复制 settings、绑定、清单能力和依赖，Snapshot 每次返回副本，避免调用者改写现役装配。摘要覆盖已解析配置和选定清单版本，用于追踪当前内部计划，不等同持久化 PipelineProfile 或部署制品锁的完整摘要。

快照不公开 settings。正式配置只包含 credential_ref，凭据由受控注入器解析；内核目前没有凭据服务或字段级密钥识别能力，不能靠“不展示 settings”替代严格配置审核。工厂应通过受控依赖取得凭据，不把凭据加入普通设置、清单或日志。

## 5. 已有证据与后续门槛

内核测试使用假设 Parser，证明端口替换、预检拒绝、能力特性、依赖槽、创建/回收顺序、错误隔离、typed nil 拒绝、取消后的迟到回收和快照副本。标准契约包另验证代际准备关系。

尚需实现并验证：

- 正式清单/部署归一化、制品锁、制品Schema注册表和生产启动检查命令；现有离线文件检查不替代它们。
- PipelineProfile 绑定、多路索引/召回、复合组及事务组合的运行装配。
- 凭据引用、真实健康/过滤/事务证明、持久化 BackendEpoch 核对。
- 两种真实解析器/存储的公共契约测试，以及迁移、回退和重启试验。
- 应用就绪入口、请求排空、任务恢复与进程退出预算。

这些门槛通过之前，内核包测试通过不能视为生产知识平台可运行。
