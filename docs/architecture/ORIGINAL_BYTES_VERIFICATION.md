# 原件与媒体的独立字节核验

`contentverify.VerifyBlobBytes` 已实现，依赖平台 `BlobStore`，可以注入本地、对象存储或其他符合契约的实现。它读取完整流，核对批准 BlobRef 中的长度及 SHA-256，要求正常 EOF 和成功关闭；超长、截断、非 EOF 错误、连续无进展读取及期限/取消均拒绝。

调用方必须先从已经验证的冻结正文中取得 BlobRef，并通过可信控制源取得适合原件读取的当前授权。该函数保持原 Scope 与 Action，不把 knowledge.search 自动转换成文件读取权限。实际所有权与当前权限由 BlobStore 的授权提供者核验。

每次最多64 MiB，使用32 KiB缓冲，不把整个原件载入内存；同时受父Context、请求期限与Scope过期时间约束。读取失败后关闭流，提供者错误映射为静态错误，不暴露内部位置。存储提供者仍须遵守取消契约，阻塞且不响应Context的远程流不能由该函数凭空中断。

局部验证包含真实本地存储的上传/读取及拒权，另有短流、长流、错误摘要、读取/关闭/Open失败、连续无进展、空文件、返回作用域隔离与取消检查。

这项能力只证明原件字节与批准摘要一致。它不证明某段文字确实来自该文件，不验证页码、单元格、OCR或表格语义，也不能把人工编辑后的正文自动认定为原件逐字摘录。当前检索候选为original/coarse；还需绑定实际批准块、来源锚点和摘录，并按格式调用相应定位/解析核验器，再进入完整CurrentBackend和输出前复核。

本轮尚未将原件核验接入PostgreSQL实库探针或产品输出链路。此前PG15/16/18各172项证据保留为其466项输入的历史基线，不能视为本轮新增模块的实库集成证明。
