# 持久化授权与封存策略

更新：2026-10-16。实现：`pkg/postgres.Authorizer`，遵守平台 `contracts.Authorizer`。本轮原生数据库验证已通过，完整生产权限管理尚未验收。

## 授权边界

认证器先验证访问令牌得到 Principal；授权器不把 Principal 当作凭据，也不读取令牌中的角色或 scope。调用方必须使用已认证主体。数据库对发行方、主体类型、客户端启用状态重新检查，并按空间当前策略版本查找全部请求知识库的明确授权。

授权键为：空间、策略版本、发行方、主体、客户端、知识库、动作。任何请求知识库缺少授权时，整个请求拒绝。空知识库列表、重复目标、未知资源、跨空间资源、资源所属知识库未在请求范围内以及不支持的委托身份均拒绝。文档资源检查不替代发布状态检查；发布与撤回由知识领域及最终证据复核负责。

同一次授权使用只读 Repeatable Read 事务获得一致的策略及身份状态，返回有限时 AccessScope，过期时间不超过调用 deadline，范围标识由随机值生成。ScopeLifetime 必须配置在 1 秒至 5 分钟内。AccessScope 仍不是可跨信任边界使用的签名授权证明，远程模块需要独立调用准入与 Grant。

## 策略更新

`access_policy_snapshots` 是空间内不可变版本，`access_policy_grants` 保存明确允许项，`access_policy_heads` 指向当前封存版本。

更新顺序：创建未封存版本 → 写入全部授权 → 封存 → 事务切换当前指针。授权记录只允许在未封存版本追加；封存后不能编辑、删除或追加。策略指针只能提升版本，不能回退或删除。撤权通过发布不含相应授权的新版本完成。业务回退也需要发布内容等效的新版本，不能复用旧版本号。

授权明细写入会锁定快照行，和封存操作串行化，避免封存同时追加授权。数据库管理员的绕过权限不属于该机制提供的隔离边界。

## 查询接入和验收

原生证据探针通过实际签名认证和数据库授权执行 `AuthenticatedControl`。每次 Refresh 都重新授权；最终证据输出前再次检查。授权撤销后后续检查拒绝，策略变化时旧请求不能继续沿用原授权版本。

本轮测试包括明确授权、默认拒绝、空间/知识库/客户端/发行方/资源限制、不支持的委托、封存后追加失败、撤权、版本倒退失败及当前证据检查拒绝撤权。测试数据仍通过受控脚本登记，不能视为已提供权限管理后台。

尚缺角色/用户组和继承策略、管理 API/UI、管理者授权及审计、正式迁移/初始化、RLS、多租户运维、远程准入、持久化 CurrentFacts 配置源及全产品集成。此实现可以由其他策略引擎替换，上层继续调用标准 Authorizer。
