# 当前发布内容的 PostgreSQL 关键词检索器

状态：默认实现及当前范围的实库验证已通过。默认实现遵循 `contracts.Retriever.Search`，业务层不引用 PostgreSQL 查询类型。

## 请求与权限边界

`postgres.KeywordRetriever` 依赖当前权威读层、平台模块实例标识及必填 `RetrievalAuthority` 回调。回调必须从可信应用计划解析发布投影并验证当前调用权限，不能把客户端提交的摘要当作授权。

检索器使用现有发布投影契约核对请求、Scope、路线、模块、配置、后端、代际和到期时间；再对照数据库当前有效发布、批准规则及原生正式发布记录。投影只可选择仍有效的来源；客户端自报版本列表不能扩权。身份或投影服务缺失、失败、过期时返回静态错误且不返回部分候选。

真实生产身份、父子授权计划及 Grant/调用账本还未接入。本次实库使用注入的权限替身，不代表生产权限系统已完成。

## 实际检索

同一主库只读 Repeatable Read 事务内，先比对当前发布事实，再读取实际封存索引快照、核对索引所属/删除状态和产物快照摘要。不能仅凭元数据 Ready 标志判断索引仍存在。

SQL 使用 `simple` 全文查询和字面子串匹配。空间、知识库、后端、代际、当前发布头和删除围栏均在排序及 Limit 之前过滤。实际索引投影保留准备时的 `Published=false`，其后不再修改；检索权限来自当前平台发布头。

候选保存平台 Document、Revision、Block、Chunk、来源位置和代际标识，不暴露后端内部位置。排序按 PostgreSQL 全文排名加字面包含分，再以代际及分块ID确定同分顺序；`score_kind=postgres_keyword_rank`，不能与其他检索器原始分数直接相加。

查询使用绑定参数，百分号和引号不作为 SQL 模式或代码执行。纯关键词实现拒绝向量、嵌入规格及额外通道；后续可替换为其他标准 Retriever，并通过融合模块按排名合并。

## 返回前检查与边界

实际检索后再次验证调用权限，另开权威读取观察点，比对发布 epoch、有效 Revision/GenerationSet、后端及当前批准/规则。撤回、换版或撤销批准导致旧请求失败，不把旧候选改成新引用。

这些是候选检索的观察点，不是数据库与网络发送之间的原子屏障。后续模型及 API/MCP 输出仍须运行最终正文/索引证据及当前身份权限复核；不因此关闭完整 CHECK 验收。

## 当前资源限制

单调用只支持一个知识库的一条关键词路线，跨知识库通过上层协调器拆分。查询最多4096字节，返回最多1000项。权威清单最多1000个当前发布头；索引完整性核验最多10000条投影、累计16 MiB，每个实际索引快照最多4 MiB。超限明确失败，不截断授权集合。

逐代际核验实际快照带来额外读取成本。尚未在生产资料量和并发下测量延迟，也没有证明中文 Recall@10 ≥90%；中文分词、向量、混合召回、重排、第二后端替换与固定条件性能验收仍需推进。

## 已取得的证据

[独立运行复核](evidence/keyword-retrieval-runtime-review.json)核对三版PG共3个实际候选、51条真实封存索引记录、发布投影摘要和请求/结果模块Schema；候选正文、平台引用、代际、排序及wire投影均作关系对照。实库14项新增场景包含具有有效结构及测试授权的未发布投影拒绝，以及索引删除前成功、删除后拒绝的对照。
