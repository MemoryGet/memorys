# 架构决策与候选组件

## ADR-001：平台契约优先，采用模块化单体

决定：平台自有应用层、领域对象和端口；外部组件只能通过适配器接入。初期单体减少跨服务事务和部署负担，耗时解析与外部引擎可独立部署。

取舍：需要自行实现一层治理和契约，不能直接把一体化平台页面当作完整产品。获得的是稳定 API、数据归属和逐模块替换能力。拆服务的触发条件是独立扩容、不同信任域或团队部署边界，不以模块数量为理由。

## ADR-002：WeKnora 首先作为远程复合引擎验证

决定：首轮采用平台应用服务 → HTTP 适配器 → 固定版本 WeKnora。并行设计独立 Parser/Embedder/IndexWriter/Retriever 端口，但不假设 WeKnora HTTP API 已经逐一暴露它们。

依据：v0.8.2 的 [解析接口](https://github.com/Tencent/WeKnora/blob/v0.8.2/internal/types/interfaces/document_parser.go)、[检索接口](https://github.com/Tencent/WeKnora/blob/v0.8.2/internal/types/interfaces/retriever.go)、[模型接口](https://github.com/Tencent/WeKnora/blob/v0.8.2/internal/types/interfaces/model.go) 使用项目内部类型，直接嵌入会使平台依赖其实现。此处选择适配边界是架构判断，不是项目原生可替换性的承诺。

平台保存标准内容和发布事实，WeKnora 内部 ID 映射到 Revision/Generation。原始文件直接由外部引擎解析的试验路线，必须能导回足够完整的标准 Block 和来源定位；不能满足时不作为正式权威内容链路。审核后标准内容能否无损写入引擎也必须验证，不能让引擎重新解析覆盖人工修改。

正式使用门槛：能隔离候选内容、准确过滤允许版本、读取证据来源、删除/导出/重建，并验证其上下文扩展不会带出草稿或未授权文本。不能达到门槛时，保留其解析等可验证能力，检索改用独立实现；不为复用引擎削弱平台规则。

## ADR-003：发布指针和权限由平台控制

决定：审核实现可替换，但状态机和强制不变量在领域层。索引准备与发布分阶段，平台元数据事务切换指针，outbox 传播后续动作。

理由：搜索后端之间无法普遍共享数据库事务。将索引状态视为发布事实容易泄露未审核内容。使用平台检查也让撤回不受索引异步删除延迟影响。

## ADR-004：允许重启替换，有状态迁移默认暂停写入

决定：采用受控注册与配置装配，默认不开发热插拔、运行时下载插件或跨库双写。切换保留配置、数据快照与兼容回退窗口。

代价：部分迁移需要维护窗口；新写入之后回退需要事件重放或反向迁移。收益：替换行为可审计、可复现，首版一致性边界清晰。

## ADR-005：嵌入、分块和索引分别版本化

决定：内容 Revision 与派生产物 Generation 分离。改变模型维度/分块策略新建索引代际；改变正文内容新建 Revision。查询不得混用不兼容嵌入规格。

## ADR-006：质量指标由固定评测集证明

决定：Recall@10 ≥90% 是约定中文测试集上的证据召回验收目标。回答正确率、引用支持率、延迟和成本单独报告；任何组件宣传指标不替代本平台实测。

## 组件能力矩阵

下表是选型与验证清单，非已完成的集成结果。软件许可、活跃度和新版本状态沿用既有调研作为线索；实施前锁定 commit/tag、许可证文件哈希、依赖清单和最近发布/修复记录。没有固定版本证据的候选均为待核验，不能直接进入生产选型。

| 模块 | 首选/对照候选 | 替换粒度与数据出口 | 过滤/治理门槛 | 许可及维护核验 | 当前结论与成本 |
|---|---|---|---|---|---|
| 复合引擎 | WeKnora v0.8.2 / 独立检索流水线 | 复合；标准 Block 往返、后端映射待验证 | KB+Revision 精确过滤，候选隔离 | 固定 tag 源码依据；主项目MIT及第三方例外已固定核验；实际镜像/依赖许可仍待核验 | 文档/部分源码证据；无运行验证；拆出内部能力成本高 |
| 文档解析 | DocReader / RAGFlow 解析路线 | 独立 Parser 适配；Block/定位导出待验证 | 解析输出不可自动发布；文件隔离 | RAGFlow 版本与部署依赖待锁定 | 表格/OCR 对照；适配成本中高 |

| 索引/召回 | PostgreSQL 全文+向量路线 / Qdrant+全文引擎 | 标准内容重建；绑定引擎版本和索引格式 | KB/Revision 过滤、删除、代际隔离 | PostgreSQL 扩展、Qdrant及全文引擎分别核验 | 需中文全文效果试验；迁移成本中高 |

| 元数据 | PostgreSQL / 另一关系数据库适配器 | 全量逻辑导出、事务包整体替换 | CAS、事务、审计/outbox 一致性 | PostgreSQL License；驱动/替代库待锁定 | 首版仅 PostgreSQL 生产目标；替换成本高 |
| 认证授权 | 内置主体/RBAC / OIDC+外部策略引擎 | 身份映射与策略导出 | 默认拒绝、机器和用户委托区分 | 服务及SDK许可待核验 | 领域契约确定；迁移需影子授权对照 |
| 审核 | 内置状态机执行器 / 外部审批引擎 | 审批、哈希与历史必须平台留存 | 回调认证、幂等、不越权发布 | 外部候选暂不选定 | 先内置；替换成本中 |
| 任务事件 | PostgreSQL 任务事实+Redis 投递 / 其它投递器 | 任务、租约、幂等结果可导出 | 重复投递、过期 Worker 隔离 | Redis 具体发行版及许可证必须锁定 | 设计确定；不能把 Redis 唯一持久化当默认 |
| 生成重排 | 云模型适配器 A / B | 无状态协议转换，评测集不变 | 引用、取消、预算和隐私配置 | 服务条款待按供应商确认 | 模型未锁定；接入成本低，效果验证必需 |
| 图谱记忆 | Neo4j/其它图存储；Mem0/Letta/自有 | 各自独立端口；平台保存来源/记忆事实 | 作用域、撤回、TTL/删除 | 具体版本、社区/商业能力边界待核验 | 可选后期；不同项目不是即插即用等价物 |

WeKnora 的 [混合检索 API](https://github.com/Tencent/WeKnora/blob/v0.8.2/website-docs/04-api/02-api-knowledge.md) 可作为预计算查询向量和 knowledge_ids 过滤验证入口；这不证明存在独立向量写入接口。其 [KnowledgeService 接口](https://github.com/Tencent/WeKnora/blob/v0.8.2/internal/types/interfaces/knowledge.go) 的重新解析行为要求适配器避免对当前发布对象原地重解析，应为候选版本使用独立后端对象。

## 需要用试验收敛的决策

1. WeKnora 经审核标准内容的写入、来源往返和隔离过滤能否同时满足契约；不能时启用独立索引路线。
2. 中文关键词检索采用哪种 PostgreSQL 扩展或独立全文引擎；以同一语料比较，不能仅看功能表。
3. 模型选择、硬件容量与延迟阈值在部署样本测试后锁定；平台端口不因此改变。
4. 大 KB 有效版本过滤的后端限制与吞吐，用真实规模验证；超限不得自动放宽权限。

这些是实现选择的待验证项，不影响已确定的权威数据、状态机、作用域和契约边界。

固定commit的进一步核验见 [WeKnora适配器设计](WEKNORA_ADAPTER.md)。已确认Markdown手工知识写入入口，可验证“标准内容作为检索投影”的路线；结构化来源往返、过滤规模和准备证明仍未验证。首轮不依赖引擎返回完整权威内容，不对活动对象原地编辑。

部署组成的进一步核验见[组件准入](COMPONENT_ADMISSION.md)：固定版本默认数据库为ParaDB镜像，基础运行依赖DocReader/Redis，latest标签须另锁制品摘要。平台权威数据与引擎内部数据库保持隔离，源码核验不等于部署或契约验收。

独立检索对照进一步采用[Qdrant向量适配设计](QDRANT_ADAPTER.md)：固定v1.16.2源码及API入口已核验，先声明vector通道；关键词、嵌入、重排仍独立配置。没有运行过滤或替换证据，不能提前作为正式实现。

## Grant验签器技术选择（2026-10-13）

首实现采用[专用紧凑JWS/JWT Profile](GRANT_TOKEN_PROFILE.md)，go-jose/v4 v4.1.5为成熟SDK候选，Ed25519固定算法及受控公钥快照。绑定、服务身份和当前授权继续独立，不将SDK类型带入领域契约。未引入Go依赖或运行验签/轮换；这项决定不关闭D-03。

## 中文关键词对照候选（2026-10-13）

独立流水线采用[OpenSearch＋SmartCN候选](KEYWORD_ADAPTER.md)与Qdrant向量分别绑定标准keyword/vector通道。3.3.2是既有Compose固定兼容基线，不是生产安全版本承诺；当次latest为3.9.0，升级/插件/维护及真实中文效果仍须验证。关键词候选补齐独立路线分工，不修改权威内容/审核/权限或提前宣布Recall达标。

## 替换融合器的数据交付边界（2026-10-16）

内置配置RRF作为受控本地计算可以在最终证据复核之前执行。通过Dependencies注入的Fuser统一按可跨模块边界处理：调用前对全部原始候选重新验证当前身份、权限、配置、审核、发布和实际来源，调用后再次复核输出。不能根据提供方自报“本地/可信”标记跳过检查。

原始候选形状与谱系校验由应用层负责，不依赖默认RRF自身实现。替换Fuser不能绕过Chunk/代际/原始贡献约束。复核方和融合器接收独立数据副本。

这是当前应用执行顺序决定，不关闭远程Grant/账本、网络发送/撤权屏障或成熟融合服务验收。测试原件读取授权按阶段预算收紧deadline，内容校验器的有效期约束保持不变。实现和验证边界见[多路由搜索](SEARCH_MULTI_ROUTE.md)。
