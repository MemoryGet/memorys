# 伙伴读取应用：实施边界与验收设计

当前读取应用及REST/MCP适配已实现，支持当前版本及独立授权的已发布历史版本，来源类型和完整运行边界见文末增量。统一依据 partner.v1.json 的 /read、ReadRequest、ReadResult，不增加供应商标识或客户端授权字段。下文保留分阶段历史记录，以最后的增量为当前状态。

## 发现的实现约束

原有 QueryReads、queryread 的范围及发布分页校验均限定 knowledge.search。当前已新增严格动作准入：共享当前内容读层允许 knowledge.search / knowledge.read，KeywordRetriever 在调用任何授权/存储依赖前仍只接受 knowledge.search；范围刷新禁止动作替换。PublishedFrozenReader 依赖同一通道。不能把读取请求伪装为搜索，不能把客户端提供的文档ID当作空间/知识库授权。

新增读取必须先建立可信文档归属定位端口，仅向认证后的应用返回空间/知识库定位，并对不存在和无权限统一隐藏。随后显式申请 knowledge.read，授权完成才加载正文。定位不得接受客户端空间覆盖；资源ID必须进入授权请求。读取当前版本和历史版本是不同授权语义。

## 应用与适配器边界

ReadService 管理临时凭据、当前认证、文档归属定位、资源授权、读取快照、版本选择、冻结内容完整性校验、分页投影和输出前再次认证/授权/发布校验。REST与MCP复用该应用。底层读取模块只能使用标准Document/Revision/Block与平台ID，不暴露SQL事务和供应商类型。

QueryReadUnit的动作准入需要明确区分search和read；全文搜索、检索器和搜索计划仍只准入search。不得全局替换动作字符串或放宽为任意knowledge.*。历史读取需要独立history权限，并仍检查当前撤回、删除与文档归属；原有PublishedFrozenReader仅支持当前发布版本，不能直接声称历史读取可用。

## 分页与来源

ReadRequest没有空间字段。cursor需要完整性保护、期限、主体/issuer/client、文档/版本、选择块集合、授权与发布快照、配置版本及排序位置绑定；不把裸数据库游标返回外部。不支持的cursor必须明确拒绝，不能忽略后返回首页。block_ids的省略、空集合、重复、不存在与顺序语义需在契约中固定。

返回标准内容块和稳定平台引用。冻结版本双哈希必须重新校验；引用定位必须与返回块一致。分页过程中发布版本变更、撤回、授权变更或cursor主体变更均拒绝继续旧快照。历史引用仍受当前权限约束。

## 必须取得的验证证据

1. 实库证明只有read授权而无search授权的用户可以读取、不能搜索；反向用户不能读取。无权限和不存在不泄露文档信息。
2. 当前/历史版本各自授权，撤回、删除、审核失效和替换发布期间不返回越权旧内容。
3. 同一封存Revision重建标准Block，双哈希、所有权、引用和定位独立复核。
4. 翻页完整且无重复，跨主体/cursor篡改/过期/块集合变化/发布变化拒绝。
5. REST和MCP经同一应用返回相同内容与引用，通过OpenAPI及工具Schema。
6. 输出前撤销凭据/权限/发布的受控故障试验；复制隔离及context取消验证。

此设计不表示上述能力已完成；需要先实现资源定位与动作隔离，再贯通读取服务、REST与MCP。

## 动作隔离实施进展

已实现共享当前内容动作白名单，不接受历史、写入或通配符；保护层保留原始动作，刷新授权不能将read转换为search。定向测试覆盖read正常准入、未知动作在底层调用前拒绝、跨动作刷新拒绝及read无法进入关键词检索授权回调。此轮是底层实现与测试，尚未取得实际数据库read授权链路、资源定位或伙伴读取运行证据；读取接口仍未开放。

## 可信文档定位实施进展

已新增标准 ReadableDocumentLocator 契约与PostgreSQL实现。调用者需先认证Principal；SQL联接当前策略头、显式read授权及启用身份，排除已删除/无当前发布版本的文档后才返回归属，随后以资源ID再次执行当前授权。返回主体授权范围，不返回正文。不存在与无权限统一ErrAuthorization。

PostgreSQL16实库试验通过：新增独立read-only测试主体和read授权，定位得到正确归属，并在重新授权保护下读取当前元数据；search-only主体定位拒绝、read-only主体申请search拒绝、缺失文档同类拒绝。该主体为数据库授权fixture，尚非真实读取令牌到伙伴接口的端到端试验。定向Go测试、架构依赖检查和go vet通过。见[实库证据](evidence/read-location-postgres16-review.json)。

当前伙伴读取应用、标准正文结果、历史读取、游标、REST/MCP读取与最终输出复核仍未实现。本轮仅PG16补验，不能将其描述为本轮三版PG均通过。

## 当前发布正文应用实施

新增 knowledge.CurrentReadService，依赖标准认证、受授权文档定位、QueryReadUnit、FrozenContentReader、CurrentFactsSource；不依赖SQL或供应商SDK。当前返回内部标准冻结内容记录，尚不映射伙伴ReadResult。

执行：复制并限期持有凭据→认证→当前read定位→同一读取快照收集有效发布事实并绑定store epoch→当前配置/审核规则/发布关系复核→读取冻结正文→比对内容和块双哈希→重新认证与定位授权→重新检查当前配置/审核与发布→返回独立副本。内容提供方获得输入副本；凭据临时副本清零。

显式revision只能等于当前有效版本，历史请求在正文读取前拒绝。当前发布发现复用有界分页收集，上限10000项/100页，达到上限失败，不作静默截断；后续应增设按文档读取发布事实端口，避免大知识库扫描。伙伴分页尚未实现，内部发布事实分页不能视为伙伴cursor已完成。

定向测试覆盖正常读取、内容损坏、返回版本错误、最终认证撤销、读取后撤回、内容适配器修改scope副本与历史请求；拒绝结果不带正文。尚缺真实令牌到该应用的实库端到端运行、伙伴Block映射与Schema、原件引用验证、REST/MCP读取、历史权限及cursor。

## 真实读取应用与伙伴投影补验

当前已将实际RS256令牌接入CurrentReadService，使用PostgreSQL显式read授权、当前配置与发布事实、冻结内容读取器完成正文读取。实库宿主为读取通道单独验证read范围，不复用搜索专用回调；QueryFacts当前内容读动作准入同步支持read，检索边界仍保持search。

新增api.ProjectReadContent：从已授权冻结记录映射伙伴Block与Citation，保持文本、结构化内容和来源锚点，补平台revision_id并移除内部order；省略块集合返回全部、显式空集合返回空、按冻结顺序输出、重复与不存在的块拒绝。规范JSON允许1e0这样的整数形式，映射按精确整数值判断顺序，避免误拒合法冻结记录。

PG16最终一次整体验证通过，新增两项原生断言；check_current_read_runtime.py独立读取实际样本，复核冻结Schema、内容哈希、发布ID、全部Block/Citation的伙伴Schema及逐字段映射一致性。本轮不代表三版PG同步通过。此前运行曾分别在任务租约、多路搜索或MCP阶段间歇失败，补充安全耗时诊断，尚未确定根因；最终一次通过不能据此证明稳定性或性能达标。

伙伴HTTP/MCP读取尚未注册。ProjectReadContent仅做映射，不授权或验证原件；历史授权、伙伴cursor、最终引用来源与发送屏障继续开放。

## 整块来源验证与REST/MCP读取（2026-10-16）

新增标准ReadContentVerifier端口，CurrentReadService必须显式装配实现；缺失、失败或取消均不返回正文。端口接收批准绑定的文档/版本/双摘要和独立正文副本，在最终重新认证、授权和发布复核之前执行。验证提供方不能修改返回正文或最终授权范围。

首个TextReadVerifier独立于检索索引，只支持最多1000个非空文本块、4MiB正文及严格粗定位revision/original锚点；所有块先做能力预检，再读实际来源。revision引用核验封存正文；original引用按blob分组，通过独立原件读取授权、实际字节哈希及投影逐字核验整个块，投影后重新授权和复核批准。人工追加内容不能借用块内一小段真实原文通过。结构媒体、精确定位、derived来源及空文本明确拒绝整次读取，不删块或改写来源。其他模块可通过同一端口实现更多能力。

伙伴POST /api/v1/knowledge-os/read仅接受标准ReadRequest，配置摘要来自可信配置身份源，并由应用当前事实复核。block_ids省略取全部，显式空集合返回空；重复/缺失块拒绝。显式revision只可为当前版本；cursor目前明确capability_missing，不能忽略后返回首页。错误不回显提供方细节，凭据临时副本清零，返回no-store。默认服务器注册路由，但没有生产装配时仍返回503。

MCP Config.Read可选注入同一读取应用；存在时注册knowledge_read并沿用生成目录的输入/输出Schema、HTTP身份和请求取消；缺失时仍只提供搜索。REST与MCP复用PartnerReadHandler，输出JSON文本和structuredContent来自同一字节序列。官方SDK真实HTTP客户端测试覆盖读取、双格式一致及非法主体/不支持游标拒绝。

新故障测试覆盖必需验证器、来源失败、验证期间撤回、输入/输出副本隔离、完整原文与编造后缀、原件拒权/投影后撤回、历史/写入/通配动作及不支持定位拒绝。521项输入在PG16通过240项原生检查；独立复核实际UTF8原件整块文本、ReadRequest/ReadResult Schema、两工具运行目录及REST/MCP字段和双格式一致。Go全量/go vet、228项Python和三份OpenAPI检查通过，临时实例目录和端口清理已独立核对。本轮未重验PG15/18，不沿用此前516项输入作为新实现证据。见[实库记录](evidence/partner-read-application-postgres16-review.json)、[独立复核](evidence/partner-read-runtime-review.json)、[全量检查](evidence/partner-read-local-checks.json)。

整体验证在新增读取运行前出现过审核重放拒绝（约473ms）和任务再次读取失败（约817ms）；两份失败记录保留。移除临时诊断后，探针将任务读取失败与正文别名分开报告，并为审核失败补充安全的准备校验和剩余预算诊断；未修改业务超时或放宽授权。之后一轮完整通过仍不证明根因已解决或稳定性/性能达标。

仍缺：历史独立授权及读取、签名快照游标、大库按文档事实读取、复杂结构/精确来源、生产Grant/发送撤权屏障、正式依赖装配和完整产品验收。原件授权探针仍为fixture，不能称生产Grant已完成。

## 按文档事实与签名分页增量（2026-10-16）

当前读取应用与PostgreSQL PublishedFrozenReader均改为按目标文档加载事实，复用QueryReadRepository.LoadCurrentDocument及PublishedCurrentFact关系核验；不再为读取一篇正文列举整个知识库。这移除了原读取路径的发布库存数量上限，不代表已有大规模性能实测。搜索库存路径保持原有独立限制。

新增标准ReadCursorCodec端口与本地HMAC-SHA256实现。部署方注入至少32字节密钥和受控key ID，模块持有密钥副本；游标包含签名、期限、页大小、排序位置、块集合摘要及快照绑定摘要，不包含凭据、正文或裸数据库游标。密钥更换后旧游标拒绝，不提供调用方算法或密钥选择。正式部署密钥供应/轮换仍待装配。

CurrentReadService.ReadPage可选配置PageSize（1～1000）与TTL（1秒～5分钟）；初页期限取TTL和当前授权到期的较早者，后续页不得延长初始期限。快照绑定主体类型/ID、issuer、client及委托、空间/KB、ACL版本、配置摘要、store epoch、文档/版本/批准/发布代际及内容双摘要；不绑定每次刷新都会变化的临时scope ID与观察水位。每一页完整重新执行认证、定位授权、当前审核发布及全正文来源验证，最后比较游标与新鲜快照；签名成功不代替授权。

REST与MCP均复用可选分页应用接口，无需修改伙伴Schema。block_ids需在继续页保持相同集合，允许输入顺序变化，实际输出按冻结顺序；省略与显式空集不同。篡改、过期、更换主体/权限/配置或发布快照的游标均拒绝，不返回部分正文。暂以统一conflict处理无效/变化游标，尚未提供精细cursor_expired错误分类。未配置分页时仍可读取完整当前正文，任何传入cursor明确capability_missing。

定向测试覆盖三页完整/无重复、每页两次认证和一次来源检查、不调用发布库存、scope ID刷新兼容、身份/权限/发布/批准/代际及store epoch变化拒绝、集合与空集隔离、签名密钥复制/更换/篡改/过期/未知字段及零值签名器拒绝。续页不能延长初始期限。签名器在来源验证后、最终认证/授权/发布检查之前调用；签名期间撤销身份或撤回发布的故障测试拒绝正文和游标。若最终授权期限比已签游标更早，整次请求拒绝，不能通过签名后的慢模块绕过最终控制。

实库分页样本按Unicode字符将同一真实原件完整拆成两个封存文本块，不重复增加索引工作量；在相同签名模块下，通过REST初页游标继续MCP次页，核对每页内容和引用、完整且无重复、双格式一致及篡改/撤销令牌拒绝。527项输入下PG16共243项检查、Go全量/go vet、228项Python与三份OpenAPI通过；实际来源/期限/两页Schema及完整字段映射独立复核通过，临时目录和端口已独立确认清理。见[实库](evidence/read-pagination-application-postgres16-review.json)、[独立复核](evidence/read-pagination-runtime-review.json)、[本地检查](evidence/read-pagination-local-checks.json)。本轮仅PG16，不能沿用旧快照称三版同时通过。

本轮诊断修正了一个探针误判：原件请求本已收紧到阶段期限时，不要求它“再次缩短”；现在核对所有实际grant不超出父请求、scope和阶段，另以明确短阶段验证必要时收紧。保留精确到纳秒、带时区的期限样本供独立复核。也保留了新增样本重复索引导致4秒租约过期的失败记录，随后改为拆分原文，未延长任务租约。

随着验证项目增加，旧探针共享的20秒总截止曾在约19.9秒导致查询阶段失败。测试宿主现将治理和查询/输出拆成各20秒的独立fixture阶段，查询阶段重新建立测试请求与授权范围；总套件最多跨两个阶段，不是同一业务请求或同一grant续期。原有业务30秒上限和任务租约未改变；这不构成产品延迟/吞吐验收。此前审核等阶段的间歇失败仍未查清，失败归档不被最终通过记录覆盖。

仍待：历史独立授权、复杂来源、生产Grant和发送撤权屏障、正式密钥与依赖装配，以及实际大库/并发/效果和迁移回退验收。每页完整读取并验证最多4MiB正文，分页只限制伙伴输出块数，不是流式正文加载或性能验收。
