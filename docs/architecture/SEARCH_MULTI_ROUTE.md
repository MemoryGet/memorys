# 多路由搜索与可替换融合

更新：2026-10-16。实现位于统一 SearchService 与 MultiRoutePlans；三版PG原生运行及独立关系复核已通过。

## 路由执行

应用服务按不可变 QueryProfile 枚举全部路由，分别固定路由 ID、通道和 CandidateLimit，调用可信 PlanSource。用户 limit 限制最终结果数量，各路由候选预算独立取自配置，候选总预算仍受 QueryPolicy 限制。

每份子计划必须保持已认证主体范围、查询文本、请求 deadline 和流水线摘要。子计划的存储 epoch 与权限版本必须一致；同一文档的发布事实必须完全一致。事实合并最多 1000 个文档，不允许混用不同观察中的文档版本。

所有子计划准备完成后顺序执行检索，共用整个检索阶段的 timeout，不给每条路由重新计时。顺序调度是当前默认实现；后续可在既定总预算内引入有界并发。每条路由结果校验数量、连续排名、路由 ID 与实际检索实例 ID，合计正文最多 4 MiB。

目前任一路由准备或执行失败都拒绝整批。即使路由声明为 optional，也暂不静默跳过；降级状态和告警响应还未接入，不能向调用方伪装成完整正常结果。

## 融合与证据

默认使用现有配置约束 RRF，实现相同来源跨路由去重并保存 FusionOrigins，记录路由、检索实例、原排名和代际。Dependencies.Fuser 可注入标准 Fuser 作为替换实现；显式配置融合绑定却缺少实现时拒绝构造服务，不静默覆盖；结果仍须校验正文/引用/ChunkID/知识库来自输入，代际和融合贡献均可追溯，不能添加未知来源或重复结果。

默认RRF是应用内部的本地计算，不表示来源真实性已证明。注入的可替换Fuser可能是外部实现，因此当前执行器在调用它之前先对全部路由候选执行完整当前证据复核；复核缺失或失败时不调用融合器。融合完成后仍执行当前身份、授权、配置、审核、发布和来源检查；启用重排时继续执行重排前后双重检查。

原始路由候选校验独立于融合器：要求有效的平台文档/修订/块/Chunk/知识库标识、非空正文、有限分数、唯一且非空的代际，不允许预先携带FusionOrigins。提供方不能依靠换成另一个融合器跳过这些约束。复核和融合器分别接收独立输入副本，避免复核方改写已固定的候选。

注入融合器的前置复核是观察顺序保证，不是网络发送/撤权屏障，也不替代远程模块Grant、调用账本或数据出境准入。原生验证仍使用本地注入的RRF实现，没有宣称远程融合服务通过验收。

查询按路由执行不等于已经完成多知识库目标拆分。每条子计划的跨库目标与投影仍由可信 PlanSource 提供，现有 retrievalplan 的完整目标库存/配额分配和生产 Grant 仍待连接。

## 验证范围

单元测试覆盖两路不同实例预算、融合贡献、重复发布事实合并、路由失败/存储 epoch 不一致拒绝及可替换 Fuser 编造内容/代际/贡献拒绝。

原生试验使用两条路由调用同一个实际 PostgreSQL 检索实例，检查 RRF 去重、双路贡献和必需路由失败时不返回部分结果。它证明编排链路，不证明向量/关键词混合检索的质量；不同实例解析已有装配测试，第二种成熟检索引擎仍待接入。

独立 Python 复算该样本的 RRF 分数、各路排名/代际贡献及配置摘要。测试宿主提供计划与调用准入，尚不是生产计划源验收。

正式降级状态、多库规划、有界并发、成熟混合检索模型、固定 Recall@10 测试集、MCP/UI 与完整生产部署验收继续开放。

当前证据：502项输入，三版PG各223项检查；全量Go/go vet、228项Python及三份OpenAPI通过。见[多路由运行证据](evidence/search-multiroute-runtime-review.json)。

融合边界增量增加替换融合器调用前的实际后端检查与调用后检查计数；复核拒绝和非法原始候选的定向测试覆盖避免回归。运行结果以最新归档报告为准。

融合前置复核的实库联调还覆盖短阶段预算：原件读取授权回调将读取deadline收紧到请求、授权有效期与当前context三者最早期限。过长的读授权继续被内容验证器拒绝；修正的是测试授权回调，没有放宽原件授权规则。注入融合器样本记录调用前一次实际后端检查，以及调用后累计两次检查。

融合边界归档：[search-fusion-boundary-review.json](evidence/search-fusion-boundary-review.json)。当前502项输入/每版223项检查，复核计数、RRF贡献和原件期限约束独立复核通过。
