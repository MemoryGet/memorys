# 统一搜索应用服务与 REST 接入

更新：2026-10-16。实现 `pkg/knowledge.SearchService`、`api.ApplicationSearchHandler`；三版PG原生数据库及本地HTTP联调已通过。

## 调用流程

传输层提取临时访问令牌和公开查询参数 → 应用服务认证 → 授权知识库范围 → 可信计划源固定发布事实与配置路由 → 调用检索器 → 重新认证/授权 → 核对当前配置、审核、发布与实际来源 → 最后再次复核身份及权限 → 返回候选。

应用输入不包含 Principal、AccessScope、发布过滤器、模块 ID 或配置摘要。配置快照由服务构造时从可信部署注入；计划源不能改写查询文本、限额、固定配置、身份范围或 deadline。检索结果必须满足限额与排序要求，且逐项绑定最终复核证据；失败返回统一错误，不返回部分来源内容。

凭据采用独立临时副本，认证调用副本和控制器副本分别清理；调用方持有的输入不被修改。整个执行不超过调用 deadline、授权过期时间和 30 秒上限；检索阶段还执行配置中的 RetrievalTimeoutMS。

## 当前执行范围

执行器已接入[多路由与融合](SEARCH_MULTI_ROUTE.md)，各路按配置执行并合并发布事实，失败时拒绝部分输出。完整多库目标库存/配额和降级状态仍待完成；单路由重排已接入[前后证据复核](SEARCH_RERANKING.md)，成熟重排模型仍待验收。服务尚不提供生成问答、反馈、记忆或反思。

PlanSource 是可信应用基础设施，负责查询快照、发布过滤器、实际路由实例和调用准入。原生联调计划源产生真实标准投影并调用已装配 PostgreSQL Retriever，但父准入/调用身份仍由测试宿主提供，不能计作生产 Grant 账本或完整计划源验收。

## HTTP 适配

`ApplicationSearchHandler` 将临时 GET 参数 q、space_id、kb_id、limit 转换为应用输入。它拒绝多个 Authorization 头、含逗号的歧义令牌、重复查询/空间字段、内部权限参数和非法编码；服务端生成 request_id，设置 deadline。响应仅展示平台引用、正文、排名与来源，不输出供应商标识或令牌，并设置 no-store。

该 GET 入口仍是临时传输，不是伙伴 OpenAPI 的完整映射。默认 memorys-server 入口仍未配置生产服务依赖，保持拒绝业务调用。MCP 尚未接入；后续应调用同一 SearchService，不能重新实现身份与来源规则。

## 验证与限制

单元测试覆盖重新认证/授权、凭据清理、计划源扩权/改写拒绝、未绑定证据拒绝和最终凭据撤销拒绝，以及 HTTP 参数边界和错误/私有字段隔离。原生联调覆盖真实 RS256、数据库当前状态/ACL/配置目录、实际 PostgreSQL 检索和最终来源复核，并经 localhost HTTP 适配调用。

最终复核通过证明在各次观察时满足条件，不是分布式撤权/网络发送屏障。生产 Bootstrap、计划源、调用 Grant/账本、正式 OpenAPI/MCP、网络发送边界及多路由仍未验收。Recall@10≥90%、并发性能与完整迁移回退也保持开放。
