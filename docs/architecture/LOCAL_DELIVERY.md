## 如何确认当前源码通过

检查 `.local/architecture-check/` 下以下报告，而不是仅引用历史文字：

- `latest.json`：`local_checks_passed=true`。
- `local-ai-postgres18-windows.json`：28 项，包括原本 CLI 的恢复与拒绝路径。
- `local-web-postgres18-windows.json`：13 项真实浏览器与恢复检查。
- `local-backup-postgres18-windows.json`：9 项真实备份工具检查。

运行报告应为 `passed=true`、`sources_unchanged_during_checks=true`，并具有相同源码摘要；
网页另核对 `frontend_build`。临时 PostgreSQL 服务停止和临时资源删除也应为真。
Windows 文件占用问题的固定回归为 `state_rename_windows_test.go`：真实句柄先复现旧目录改名失败，
随后验证短暂占用恢复、持续占用有限拒绝、并发目标不覆盖、长路径支持；
`state_errors_test.go` 验证诊断不泄露路径、凭据或私钥正文。

## 使用与后续范围

用户在本机终端运行 `tools/start-local-web.ps1`，按需输入数据库密码，
打开 `http://127.0.0.1:8080/local/`，用自己的文件核对解析正文后明确发布。
日常说明见 [网页](LOCAL_WEB.md)、[AI 配置](LOCAL_AI.md)、[备份恢复](LOCAL_BACKUP.md)。

目前的功能边界仍是小型个人本地版：语义检索最多512片/512 KiB，正文级引用；
PDF 以可提取文字为前提。OCR、精确页码/单元格引用、中文质量指标、生产规模性能、
多人网页登录与生产 IAM、跨数据库主版本升级和在线灾备属于后续工作。
`production_acceptance` 保持 `false`；局部实测不能声明整个知识平台已完成生产验收。
